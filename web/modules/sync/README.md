# 数据同步页面

`/sync` 提供数据源卡片；`/sync/ns` 独立提供采购订单、子采购订单、报关单拉取；`/sync/lemon` 提供柠檬云数电进项XLS文件导入，API与附件同步仍未接入。旧模拟同步页面及虚构任务记录已移除。

SyncOverview.tsx 保留原同步中心的三列平台卡片、对账数据管道及任务记录表布局；点击 NS 或柠檬云卡片进入对应同步页，子页面可返回中心。尚未接入的统计和任务历史显示明确空状态，不展示虚构记录。

SyncPage.tsx 管理 UI 和请求状态，api.ts 提供请求契约，sync.css 限定模块样式。SyncWorkspacePage 装配公共 AppFrame。复用 identity 本机会话和 shared HTTP 客户端。

公共 HTTP 客户端对空响应、非 JSON 错误页和网络中断显示中文提示；有效的后端错误说明继续展示，不回显代理原始正文。错误不触发自动重试，可通过“重新加载配置”手动重试。`npm.cmd run test:http` 覆盖响应解析与网络失败，已纳入 `npm.cmd test`。

NS 每页最多拉取 20 张单据，展示详情、时间、空结果和失败状态。“仅拉取首页”不写数据库；子采购单和报关单的“拉取首页并保存”会补齐主从数据并写入独立 MySQL，显示提交后的新增／更新计数。保存后的翻页沿用保存模式，重复来源更新原记录。按钮使用后端 allowed/reason 和 storageAllowed/storageReason，后端执行时再次校验。标准采购订单缺少独立存储映射，保存禁用。

拉取并保存同时按NS报关引用补齐对应子采购，并保存可读取的原始报关行、装箱明细及采购行关联依据。页面展示后端 `storage.relations` 统计和 `warnings`：已读取、待补齐及来源行数；依据读取不代表匹配完成或审核通过。原始报关行接口未部署时明确显示待补齐，不用“完整同步”掩盖缺失。

页面只保留各类型当前页的展示结果，刷新清除展示；保存成功的 MySQL 数据不会随刷新丢失。保存连接中断时提示先核实本地数据，不自动重试。当前没有本地历史浏览页面，按 PL 查询仍可使用已有受保护接口。柠檬云文件导入由应用层装配[发票组件](../invoice/README.md)，先预览再确认，结果来自真实数据库；不把文件导入称为API同步成功。

NS 子页面仅展示 NS 内容与返回中心入口。使用原生单选控件选择单据类型，默认报关单；每次只显示当前类型的拉取面板。切换时保留各类型的请求及结果状态，不自动拉取，不混入其他平台入口。

NS 页面采用左侧单据选择、右侧结果工作区，窄屏改为上下布局。结果区集中展示拉取操作、只读标识、加载反馈与空状态；不可拉取时展示后端原因，失败后保留已有结果。底部说明结果仅在当前页面保留。

结果区支持按记录创建日期选择起止范围（含起止当天，按 NS 查询时区）；两项留空时不限定日期。“清空日期”只修改条件，不自动请求。后端负责日期格式、范围与顺序校验，并在 NS 源端筛选。结果显示实际提交的日期范围；修改条件后提示旧结果仍保留并禁用下一页，重新拉取首页后再继续分页。切换单据类型保留各自的输入及结果。

接口及配置见 [后端同步模块](../../../backend/modules/sync/README.md)。验证使用 build、lint、typecheck 和浏览器页面检查；后端模拟测试覆盖成功及空结果，真实 NS 联调单独验收。
