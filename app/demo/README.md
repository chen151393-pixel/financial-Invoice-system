# 旧界面演示

演示页面与真实 PL 核对共用导航、页头和内容框架；当前页明确显示数据来源。`DemoApp.tsx` 负责入口装配与 URL 导航，`web/app/navigation.tsx` 维护全站菜单，复用 `web/shared/components/AppFrame.tsx` 与 Sidebar。七个业务演示页面仍使用 `fixtures.ts` 的虚构列表，`components/SourceHealth.tsx` 提供共用展示。

PL 菜单已改为打开正式页面 `/pl-reconciliation`。Vite 主应用兼容旧 `/demo?view=pl` 地址并转到正式入口。该页面只在用户提交查询后，通过后端真实读取 NS；说明见 [核对模块](../../web/modules/reconciliation/README.md)。已移除旧 PL 模拟页面、数据文件、场景控件和静态 Excel，避免与真实结果混淆。

其他演示页面仍通过 `web/app/DemoPage.tsx` 按需加载原型 CSS 和数据，演示按钮不操作 NS。`app/page.tsx` 保留旧 Vinext 原型入口，独立原型构建不承载真实 API；实际 PL 查询请启动本项目 Vite 和 Python 后端。

原型维护运行 `npm.cmd run test:prototype`；正式前端构建和类型检查也覆盖其导入。

## 供应商通知示例

任务详情顶部的六个流程节点均可点击，通过键盘 Enter 或空格也可操作。节点分别打开财务审核、开票资料、供应商通知、收票进度、比对结果和完成情况，并定位到内容区；下方页签与节点选中状态联动。节点下仅保留流程状态，不展示“查看详情／正在查看”操作提示。查看节点不会推进任务状态，未开始的节点展示等待原因，未完成任务不会因点击“完成”而改变状态。

入口：`/demo?view=invoice-followup&task=KP-202609-001&tab=notification`。在开票跟进详情的“供应商通知”页签中，展示接收信息、通知内容、合同附件名称和通知记录。状态选择器可查看未绑定企微外部群、待创建通知、创建通知中、待员工发送、已发送、人工登记已发送、创建通知失败、结果待核实八种场景，并同步展示流程节点。

`pages/SupplierNotification.tsx` 负责示例表单、内容预览和通知记录，`supplier-notification-data.ts` 提供虚构场景。外部群绑定仅在当前页面内有效，刷新恢复；演示重试仅切换展示状态，不调用业务接口、不创建发送请求。员工发送任务已提交、已发送或结果待核实时禁用外部群绑定修改，结果待核实不提供重试入口。合同只显示名称和共享盘保存状态，不提供 PDF 下载。

“演示创建通知”只进入“待员工发送”，不会跳到等待收票；“演示员工确认发送”才展示查询到发送成功后的进度。接口接入前的人工路径提供复制示例通知文字、发送时间和说明表单，登记后显示“人工登记已发送”，保留群与对接人快照，明确未经企微接口核验。复制按钮仅复制虚构文字，不复制合同文件、不发送消息；所有登记只保留在当前任务详情内。

通知正文默认按本次采购生成，未提交通知时可直接编辑或恢复默认模板，预览和复制统一使用当前正文。修改在当前任务详情内保留，切换节点不丢失，刷新恢复；通知已提交、结果待核实或已有发送记录时只读。人工登记保留当时的正文快照。空正文时禁用创建、复制和人工登记，仅作为演示表单反馈，正式业务校验仍需后端实施。

通知对象固定为供应商企微外部群，展示群名称、内部对接人和接收快照；表单中的群名称仅用于演示，正式绑定需由后端保存可识别的外部群信息。

这些是拟接入企微外部群通知前的交互示例，供应商配置持久化、员工发送任务创建、附件传送和发送结果查询均未接入。验证使用前端构建、lint、类型检查及 `node --experimental-strip-types --test tests/invoice-followup.test.mjs`；交互需在浏览器检查。

进项发票列表使用 6 条演示样本，搜索与状态筛选组合生效，标签数量随搜索结果更新；底部展示实际匹配数量，无结果时可清除筛选。顶部金额卡片是全量模拟概览，不代表样本统计。异常行按状态进入异常处理页。搜索框和备注框提供可见键盘焦点；上述交互不调用真实业务接口。
