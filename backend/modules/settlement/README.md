# settlement 模块：结汇对账

## 职责

报关之后的结汇：客户货款必须与报关金额一致。按报关单“贸易国”分两条回款路径：

| 路径                  | 判定                 | 资金流                     | 对账                                                                                 |
| --------------------- | -------------------- | -------------------------- | ------------------------------------------------------------------------------------ |
| `hk_transit` 香港中转 | 贸易国为中国香港     | 客户 → 香港账户 → 汇回境内 | 两段：香港到账对报关合计；汇回境内对报关合计。批次与汇回一一对应（按资料一单一单做） |
| `direct` 直接收汇     | 贸易国为真实客户国家 | 客户 → 境内账户            | 总账：按境外收货人、收款人和币种汇总，出口加、收汇减，不建批次                                 |

**香港中转——差额只认手续费**：到账金额 + 手续费 = 报关合计，严格相等才通过；手续费超过 `SETTLEMENT_FEE_ALERT` 时提示复核，防止把少收款当作手续费。登记回款建批次、提单与销售合同、汇回结汇只适用于香港中转。

**直接收汇——总账（2026-11-18 业务确认）**：非香港中转的报关单不建批次，进入“直接收汇明细”。按境外收货人、收款人和币种汇总期初、本期出口、本期收汇和期末差额，同一天的流水先展示出口；余额为正是未收，为负是超收。出口取海关回执的出口日期与成交总价，出口抬头取 NS 报关单的申报主体；收汇取银行收汇明细，按表格中填写的实际客户归到收货人。付款人户名与实际客户不同即三方代付，只作标记，不影响归属，也不判断是否有代付协议。香港公司汇回境内的款项不进总账。金额或币制有问题、没有境外收货人的直接收汇报关单不计入总账，在页面上单独列出原因。

> 海关回执导入文件目前不含“贸易国”。未取得贸易国时，按境外收货人是否为集团香港公司判定（`SETTLEMENT_HK_CONSIGNEES`，分号分隔；为空时使用 `policy/route_policy.py` 内置名单）。NS 报关记录字段 `custrecord_swc_country_body`（值 95 为中国香港）同步进 source 后，可直接传入 `route_of()` 的 `trade_country`。

## 拥有的表

直接收汇明细按境外收货人、收款抬头及币种对账。选择起止日时，开始日前的出口与到账累计差额为期初，起止日当天计入本期。出口使用海关回执出口日期，收汇使用银行实际入账日期。选择期间时，缺出口日期的报关单单独提示。

总账按报关金额和实际到账金额汇总。展开可查原始流水、来源单据编号及每笔后的余额，从期初差额起按时间顺序加出口、减收汇。

- `settlement_batches`：结汇批次（一笔回款），含到账、手续费、汇回、状态与经办人。
- `settlement_batch_items`：批次包含的报关单，建批次时冻结海关回执成交总价；`active_declaration_no` 唯一约束保证同一报关单只在一个有效批次中，作废后释放。

- `settlement_bills`：批次的提单文件及提单号、装运口岸、目的口岸、装船日期、对应的报关单；移除为软删除。
- `settlement_contracts`：按模板生成的销售合同 PDF（批次内每个出口合同号一份）及生成依据摘要。
- `settlement_parties`：销售合同买卖双方抬头（中英文名称、地址、电话）与印章图片。
- `settlement_bank_receipts`：银行收汇明细（收汇日期、收汇抬头、付款人户名、实际客户、币种、金额、流水号）；规范化名称 `customer_key` 用于归属境外收货人，`payer_key` 与它不同即三方代付。

文件本体（提单、合同 PDF、印章图片）保存在 `SETTLEMENT_DOCUMENT_ROOT`，只用服务端 UUID 命名，数据库记录标识与校验值；部署时该目录须为持久卷。

结汇迁移见[表与迁移对照](../../../docs/mysql/schema-map.md#settlement)。已有银行流水允许交易时间和导入去重摘要为空。

## 银行流水导入

- 支持银行导出的 .xlsx，按双语表头中的中文列名识别，只保存「来账」。境外收货人名称为实际客户。
- 按银行流水号或原始交易字段识别重复记录。缺少流水号及交易时间时，按原文件和行号识别重传。同一笔流水的客户、付款人或金额冲突时，提示行号并回滚本次导入。
- 每笔保存来源文件名、Excel 行号和导入人，导入结果列出新增、重复和跳过的笔数。

## 读取依赖

- `review.public.settlement_declarations`：海关回执当前版本（境外收货人、出口日期、出口合同号、成交总价）；只取已匹配到 NS 报关单的回执。汇总与总账需要完整历史，传 `limit=None` 读取全部。
- `review.public.settlement_declaration_lines`：海关回执当前版本明细（品名、规格、数量、单位、成交总价、出口合同号），供生成销售合同。
- `source.public.declaration_refs_by_number`：真实报关单号 → NS CD 编号（展示）。
- `source.public.declarant_names_by_number`：真实报关单号 → 申报主体名称（出口抬头）。

不发布、不订阅事件；`public.py` 暂无对外函数。

## 状态

```text
香港中转：collected 香港已收 → documents_ready 资料已出 → settled 已结汇（汇回对平）
未结汇前均可 cancelled 作废，作废释放报关单。
```

直接收汇不再建批次。此前已建的直接收汇批次（`collected 已收款 → settled 已结汇`）仍可结汇或作废：`BatchService.settle()` 与 `batch_state_policy` 中的 `DIRECT` 转换只为这些旧数据保留，调用方是批次详情的“确认结汇”；页面已不再列出直接收汇批次。确认库中没有未完结的直接收汇批次后（核对语句见手动执行脚本）一并删除。

状态转换集中在 `policy/batch_state_policy.py`；可操作判断（`allowed/reason`）由后端返回，执行时再次校验。

## 结汇资料（香港中转）

香港中转批次在“香港已收”阶段准备资料，**提单与销售合同齐全后才能确认资料已出**；确认后资料只读，仍可下载。

- **提单**：上传 PDF（单个不超过 8 MB）。有文字层的提单由 `policy/bill_parse_policy.py` 从文字中识别提单号、装运口岸、目的口岸、装船日期。**扫描件**（无文字层）由 `service/bill_ocr.py` 取第一页图像、去掉彩色底纹后调用本机 tesseract，`policy/bill_layout_policy.py` 按“标签下方 / 右侧同一栏”的位置取值；同一页用两种方式各识别一次，**结果一致的字段才采用**，装船日期的数字写法与英文序数写法（OBD）不一致时不取。识别不到的留空由人工填写，不猜测港口。扫描识别可能认错字符（如 0 与 O），识别出的提单标“待核对”，经办人对照原件点“修改”保存后提示消除。未安装 tesseract 或 `SETTLEMENT_OCR_COMMAND` 留空时，扫描件字段全部人工填写。每张提单标明对应的报关单（默认批次内全部）。
- **销售合同（即形式发票，2026-11-18 业务确认）**：按 `templates/sales_contract.json`（由原人工模板整理的版式与条款）生成 PDF，批次内每个出口合同号一份。明细与金额取海关回执成交总价，单价 = 成交总价 ÷ 成交数量（仅展示）；签订日期 = 最早出口日期往前推 `SETTLEMENT_CONTRACT_LEAD_DAYS` 天（默认 28）；装运口岸、目的口岸取对应提单；买方按境外收货人匹配合同抬头，卖方、成交方式、付款条件由经办人确认。双方印章取合同抬头的印章图片，缺印章时照常生成并提示。
- **需重新生成**：提单口岸、海关回执明细、合同抬头或印章变化后，已生成合同的依据摘要不再一致，须重新生成才算齐全。海关回执换版导致合计与建批次时不一致时，须作废批次重建。
- **报关单**：取 task 模块从 NS 下载并归档到共享盘的报关单原件（`task/public.py` 的 `archived_declaration_files`，只读），按原件格式（PDF 或 NS 打印模板的 xls）放入资料包，不转换格式；读取时核对归档校验值且路径须在共享盘目录内。**未归档只提示、不阻止确认资料已出**，需到“开票跟进”的任务详情下载。结汇模块自身不下载、不改归档记录。
- **资料包**：齐全后可下载 zip，结构为“批次 / 出口合同号 / 销售合同（形式发票）、提单、报关单”，附文件清单；未能放入的报关单在清单中注明原因。
- 中文字体：默认使用 PDF 内置 STSong-Light（不嵌入，英文数字用 Helvetica）；配置 `SETTLEMENT_PDF_FONT`（TTF 路径）后改为嵌入该字体。

## 尚未实现（计划）

- 直接收汇明细每次读取全部直接收汇报关单与收汇记录后在内存中累计，数据量明显增大后需改为预汇总。
- NS 客户收款与核销记录同步：尚未接入，直接收汇的收汇目前只来自银行收汇明细。
- 贸易国字段同步（见上方说明）。
- 报关单 xls 原件转 PDF（需在服务端安装 LibreOffice 之类的转换程序）未做，资料包内保持原件格式；报关单未归档时不强制。
- 提单与报关单的交叉核对（提运单号、件数、毛重、柜号）：本地尚未同步报关单的这些字段。
- 提单解析已用 HMM（现代商船）、PIL（太平船务）及阳明扫描件校准；其他船公司版式、手机拍照件、多页图像未验证。按船公司的专用解析模板、从共享盘批量导入未做。
- 扫描识别的提单目前只提示“待核对”，不强制人工确认后才能生成合同。
- 成交方式、付款条件取自 NS 销售订单（目前由经办人确认，默认值来自模板）；商品英文名（目前使用海关回执中文品名）。
- 合同抬头与印章的维护目前只受 `settlement` 页面权限控制，未单独限制为管理员；资料包下载未留下载记录。

### 扫描提单识别补充（2026-11-19）

扫描件支持 `B/L No.` 与 `Bill of Lading No.` 标签；整页识别有歧义时，仅对两次均定位到同一提单号词框的区域放大复识，局部两次结果一致才采用。不以订舱号替代提单号，不猜测号码中的相似字符。装船日期允许标签同行留白，仅在明确的 `日-英文月份-年` 日期日字段修复 O/0，不取上方签发日期。两次仍有歧义的字段留空，并保留人工核对提示。已有上传记录不会因规则更新自动重算。专项回归见 `test_settlement_bill_ocr.py`。


扫描表格提单补充（2026-11-19）：整页港口或装船日期结果有歧义时，按实际横竖表格线定位栏位，将标签与值分开，对值区域放大并用两种方式复识；两次均能按原标签解析且一致才采用。横线小缺口不截断栏位，未定位到邻近表格线时放弃局部复识。日期标签与数值之间的宽留白不再当作新栏目；只在同一行完整日期格式匹配时取值，签发日期仍不能替代装船日期。表格装船日期即使整页两次结果一致也做局部复核，降低表格线使两次同时把 1 误读为 4 的风险。直接收汇和香港中转共用此实现。测试见 `test_settlement_bill_cells.py`，私有提单原件不纳入仓库。
