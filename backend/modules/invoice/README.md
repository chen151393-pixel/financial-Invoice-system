# 发票 Excel 导入

已实现柠檬云数电进项 `.xls` / `.xlsx` 的预览与确认入库；尚未接入柠檬云API、附件、导入历史列表和自动匹配。页面为 `/sync/lemon`。

## 职责与接口

- `controller.py`：认证依赖、DTO及用例调用；`dto.py`拒绝额外字段。
- `parser.py`：读取34列票头商品合并表或“发票信息”“货物信息”双表，校验文本票号、日期、金额、精度及逐票合计。
- `service.py`：签名预览、来源冲突、权限范围、长度校验、整批事务。
- `dao.py`：MySQL命名锁及SQL；`entity.py`反射已有结构；`mapper.py`纯入库转换；`vo.py`返回中文结果及十进制字符串。

| 接口 | 用途 |
| --- | --- |
| GET `/api/invoices/import/configuration` | 检查数据库及扩展字段，返回allowed/reason/maxBytes |
| POST `/api/invoices/import/preview` | 解析、检查重复及冲突，不写数据 |
| POST `/api/invoices/import/confirm` | 重新解析与检查后，整批原子入库 |

POST使用JSON：`filename`为无路径原文件名，`content`为原文件base64。确认另传预览返回的`previewToken`；不接收前端金额、业务行、租户或权限字段。预览签名绑定操作者、文件名、文件摘要和30分钟有效期，后端重启后须重新预览。确认时仍查数据库，预览不保留数据库锁。

上传原文件最多4MiB、1000张票，每个源工作表最多6000行。仅两条导入路由将JSON请求上限扩大为6MiB，其他API仍为128KiB。使用`xlrd==2.0.2`读取XLS、`openpyxl==3.1.5`读取XLSX，配合defusedxml防护XML实体。两种格式共用业务校验与去重逻辑，不接受仅改后缀的文件、CSV或HTML。XLSX解压总量限32MiB、压缩包成员不超过1000；拒绝含宏文件，导入工作表中的公式须先粘贴为值，长票号及税号必须为文本。日期单元格及常见百分比格式可读取，不读取外部链接。

## 数据与事务规则

依赖用户已迁移的[发票两表扩展](../../../docs/mysql/invoice-excel-design.md)，不自动建表或改库。启动使用已有`BUSINESS_MYSQL_*`／`BUSINESS_DATABASE_URL`；导入配置检查会阻止旧字段结构或数量精度不足。

- 租户沿用现有业务模块的认证owner SHA256；文件不能指定租户。来源为`excel`，每个租户内固定导入空间`lemon-excel`，不宣称是已授权的柠檬云账套。
- 先完整校验工作簿，再仅选择原表业务类型为“采购固定资产”的发票及明细。其他类型跳过，不改写原业务类型，不清理既有记录。没有符合条件的发票时禁止确认。响应的`sourceInvoiceCount`为原文件票数、`excludedCount`为跳过票数、`businessType`为导入类型；其他计数、金额和`rows`仅统计筛选范围。
- 本期仅支持20位文本号码的数电票。来源键按规则版本、数电标识、票号生成。同一租户已有同号码其他来源，也视为冲突待核实，不擅自合并。
- 内容摘要忽略明细排列顺序，重复商品行按出现次数保留。完全相同跳过；内容变化不覆盖，存在任一冲突则整批拒绝。
- 每次预览/确认按租户获得MySQL命名锁；确认在同一事务保存所有新票及明细。唯一约束保留，SQL异常不返回成功。提交断连提示先重新预览核实；重复提交仍经幂等判定，不自动重试写入。
- 负金额、已红冲、免税／不征税及八位数量原样保留。购方税号、币种和单价不猜测；新票`validation_status=review`，`detail_sync_status=complete`仅表示文件票头与明细完整，不表示可匹配。

## 用户图片单票录入

`InvoiceService.import_image_snapshot`供已人工核对的用户图片摘录使用，沿用同一租户锁、同号冲突检查、两表事务及 DAO。来源标记为`manual/user-image`，保存图片文件名、SHA-256及原始摘录；再次提交相同内容跳过。图片未提供业务类型和可核实状态时分别保留`NULL`和`unknown`，校验状态为`review`，不纳入上述“采购固定资产”Excel筛选。超出明细表八位小数精度的票面单价只保留在来源快照，标准单价字段为空。当前仅有人工调用入口，没有图片上传 API 或自动 OCR。
- `source_data`保存采用文件名、摘要、操作者、时间、原始票头／明细及行号。它不是所有导入尝试的审计日志；页面刷新后须重选文件核实，没有持久任务历史。

## 合并表格式

支持用户提供的34列合并表，工作表名称不限。列顺序为原23列票头字段加11列商品字段；两个“税率”列按位置分别映射，不互相覆盖。同票号重复票头必须一致，按票号归组保存一张主表及全部商品行。商品名称为“合计”的行仅校验金额、税额及提供的数量，不保存为商品；合计行及真实工作表名、行号保留在来源JSON。多个合并模板或同时包含双表模板时拒绝歧义文件。XLS/XLSX均支持。

## 真实发票查询

- `GET /api/invoices`：当前身份的有效进项发票。参数 `q`（票号、供应商名称或税号，最长100字符）、`status`（normal/red_offset/void/unknown）、`date_from`/`date_to`（开票日期，含边界）、`page`（从1开始）、`page_size`（默认20，最大100）。所有搜索、筛选、分页及统计在后端完成；同日期按主键倒序稳定分页。
- 返回 `total/page/pageSize/hasPrevious/hasNext/rows/amounts`。`amounts`按当前筛选范围和币种分别汇总，空币种单独标记待核实，不合并不同币种。金额为十进制字符串，主键为字符串以避免浏览器整数精度丢失。
- `GET /api/invoices/{id}`：票头公开字段、数据校验原因和有效商品明细。始终校验租户、有效状态及进项方向；不可见发票统一404。不返回原始来源JSON或操作者身份，不调用NS、不写数据库。
- 查询沿用导入的身份owner SHA256隔离；列表未显示其他身份导入的记录属于预期行为。匹配模块通过注入的 `invoice_details` 批量读取当前页票头与明细，沿用相同权限范围；任一发票不可见时整体404。关联方式、置信度和匹配校验由匹配摘要接口提供，不改写发票原始状态或导入校验。可抵扣金额和NS回写状态仍未接入。
- 2026-09-23验证：当前MySQL只读查询27张，合计1,521,719.100000；独立33319端口页面验证真实列表和商品详情。四项隔离SQLite用例覆盖查询、金额分组、分页、日期、身份隔离及HTTP校验，不代替MySQL并发测试。全后端289通过、58项专用数据库测试跳过；build/typecheck/lint/lint:api及架构检查通过。浏览器在进一步分页检查时超时，窄屏与后续交互未完成浏览器验收。
