## 来源保存、审核、开票任务与发票匹配的阶段记录

NS“拉取并保存”已接入完整流程：同次读取报关、关联子采购、原始行、Packing及交易行依据，复用NS v3脚本的逐行关联与分摊结果，原子保存到独立表 `customs_reconciliation_results`。财务列表直接读取数据库构建逐级展开，未审核单据进入待审核，由财务人工核对后整单通过，不设置机器“关联核实”前置步骤。接口缺失、旧版、读取失败或范围变化时整页不保存，不再将缺少必要接口的同步视为成功。需先运行 `npm.cmd run db:business:upgrade`，增量版本为 `0005_customs_relations`；表字段见[关联结果表说明](../../docs/mysql/customs-reconciliation-results.md)。**正式接口尚未部署，本次没有将120张历史正式单据标记为关联完成。** 配置和字段见[同步来源关系说明](../../docs/finance-source-reader.md#同步时保存的对应关系)。

财务审核按已入库内容保存不可变快照、审核人、时间和备注。提交前检查本地来源变化，并与同步互斥；未分摊的子采购原值不会因审核自动成为可开票额度。见[财务审核说明](../../backend/modules/reconciliation/README.md)。

新审核通过后，在同一事务中按报关单＋供应商＋采购公司＋币种自动生成开票任务；重复审核不重复创建，来源重新审核保留历史任务版本。正式页 `/invoice-followup` 默认按供应商，可切换按报关单查看。需应用库迁移 `0006_task_notifications`（`npm.cmd run db:upgrade`）；历史审核不会自动补建。审核通过即进入下载子采购订单，无二次范围确认。任务独立详情支持从专用 NS RESTlet 获取合同并按下载日期保存到共享盘，文件名为子采购订单号+供应商；共享盘保存成功才完成资料准备。页面不提供 PDF 下载入口。供应商通知支持默认正文编辑、本任务外部群信息保存、人工发送登记和历史追溯；企微自动发送及任务收票比对尚未接入；详见[实现边界和接口](../../backend/modules/reconciliation/README.md#审核后开票任务已实现)。

2026-09-24已将120张正式报关单的历史依据迁入 `customs_reconciliation_results`，旧JSON关系键已移除，八张来源业务表及依据内容核对一致。同步和财务查询均使用新表。

2026-09-24已为本地120张正式报关单补存可用关联依据：去重后1062条Packing、995条销售采购关系、1586条母采购来源行。当时只更新报关主表中的关系JSON，原单据及采购数据未变；原始行接口仍未部署，120张的技术依据仍为partial；财务页面人工审核状态独立显示为待审核。详见[补拉结果](../../docs/finance-source-reader.md#正式来源依据补拉结果2026-09-24)。

发票匹配页 `/matching?invoiceId=本地主键` 已扩展备注采购单定位、逐项差异和人工数量分配。只比较柠檬云发票与 NS 子采购单，确认保存本地关联、不写 NS；支持分批及多单分配、重复请求幂等和来源变化待复核。启用确认前运行 `npm.cmd run db:business:upgrade` 应用新增业务迁移 `0004_invoice_allocations` 并重启后端。购方、币种缺失等仍禁止确认，见[匹配模块说明](../../backend/modules/matching/README.md)。下文历史阶段中的“尚未实现匹配”以本段和模块说明为准；柠檬云 API 仍未接入。

匹配模块新增整票关联接口，可一次将发票明细匹配至多张子采购单。数量和人民币含税金额按发票行汇总核对，不要求人工输入分配值；需要应用业务迁移 `0007_invoice_purchase_links`。正式匹配页提供候选勾选和整票确认，原有数量分配收在候选明细中；见[接口与规则](../../backend/modules/matching/README.md)。

匹配页已补齐供应商名称差异报警和手动搜索子采购单。供应商不一致不再显示高可信；存在名称、品名、单位、数量／金额等匹配差异时，可核实后勾选并填写说明确认本地关联，保留差异及确认快照。购方、币种、明细完整性、重复占用等仍由后端校验。此扩展复用现有关联表，无新增迁移，更新后需重启后端。

基础业务库已扩展为母采购、子采购、报关、发票八张来源表；迁移 `0002_parent_relation_status` 区分待核实／确认无母单／已关联，`0003_customs_price_precision` 保留报关单价来源精度。使用 `npm.cmd run db:business:upgrade` 增量升级。已完成正式环境最近一个月的手动关联导入：120 张报关（含34张范围外关联单）、194 张子采购、173 张母采购。无母单需 REST 与独立查询交叉核实，源空金额保留 NULL 并标记待核实。网页母采购自动拉取、定时同步及发票分配尚未接入，见[八表关联说明](../../docs/mysql/eight-table-relations.md)。

柠檬云工作区 `/sync/lemon` 已增加数电进项 XLS / XLSX 文件导入：拖拽或选择文件、仅筛选“采购固定资产”、解析预览、金额校验、重复跳过、冲突阻止及整批确认入库。使用已扩展的业务库发票两表，购方和币种缺失标记待核实；柠檬云 API／附件拉取仍未接入。配置、范围及验证见[发票导入模块](../../backend/modules/invoice/README.md)。

使用后端 M2M 凭证连接 NetSuite，完成“拉取记录 → 人工校对 → 生成预览 → 确认写回”。前后端独立开发和构建，部署时共用一个域名。

进项发票页 `/invoices` 已接入真实业务库，支持按票号／供应商／税号搜索、开票日期和状态筛选、后端分页、按币种汇总及商品详情。旧 `/demo?view=invoices` 进入正式页。仅显示当前身份导入的数据，未接入的匹配和NS关联不展示模拟结果。

## 页面、集成与模块拆分的阶段记录

数据同步已拆为 `/sync` 数据源入口、`/sync/ns` NS 拉取页和 `/sync/lemon` 柠檬云页。NS 支持标准采购订单、子采购订单、报关单分页拉取，每页最多 20 张。子采购订单和报关单支持“拉取首页并保存”，补齐完整明细后写入独立 MySQL，重复来源更新原记录；标准采购订单尚无独立存储映射。定时增量同步和柠檬云接口待接入。配置与接口见 [同步模块说明](../../backend/modules/sync/README.md)。旧 `/demo?view=sync` 自动进入新页面。

已将 [财务核对](http://localhost:5173/finance-reconciliation) 接入正式项目的独立导航与页面，原 [采购报关联查](http://localhost:5173/pl-reconciliation) 保留为只读来源对照，两个页面不合并。财务核对复用NS来源追溯规则，按“报关单 → 报关行 → 子采购行”逐级展开，默认收起；PL与申报公司位于主单行，数量、单位、单价、金额对齐。主单支持整单审核并保存本次范围、身份、时间、备注及审计记录，提交前重新核实NS。**本地NS v3适配代码已完成，尚需上传两份脚本并验收真实权限和数据；旧接口不能推断行关联或审核。** 独立5191预览目录、启动配置、模拟页面和临时验收服务已清理，两个正式页面均由项目 `npm.cmd run dev` 启动。见[模块说明](../../web/modules/reconciliation/README.md)和[部署说明](../../docs/pl-script-integration.md)。

历史 Vinext 原型保留 `dev:prototype`、`build:prototype` 和 `test:prototype` 脚本。`.openai/hosting.json` 仍被原型构建引用；Cloudflare 仅供这条原型预览链路使用，不属于 Python 后端的部署要求。未接入的 ChatGPT 登录、D1/Drizzle 示例及旧 Node 后端已移除，现有业务数据和 Python 数据库迁移继续保留。

`.next/`、`.vinext/`、`.wrangler/`、`.ruff_cache/` 是工具生成目录，可在相关进程停止后清理，后续运行对应工具时可能重新生成。`.venv/` 和 `node_modules/` 是已安装的运行依赖，不作为无用文件删除。

## 当前能力与边界

旧“记录校对与写回”和“PL 单联查”页面及导航已删除，首页进入 `/pl-reconciliation`。后端仍保留 PL 联查能力：复用 NS 读取链路，按 PL 联查采购及关联报关明细。本机沙箱映射已配置，并通过 `PL2510280002` 的真实只读联查；其他部署仍需配置环境变量。映射可读副本见 [完整字段 JSON](../../docs/netsuite-pl-lookup.json)，配置方式与验证边界见 [PL 单联查说明](../../docs/pl-lookup.md)。不依赖已保存搜索，不做自动商品匹配或金额分摊。

NS规则来源为本地 `SuiteScripts/pl_lookup`（按原忽略规则不纳入仓库），最新脚本状态见该目录README；[早期Suitelet方案](../../docs/ns-suitelet-realtime-plan.md)仅作历史设计参考。网站新增的 `scripts/netsuite/pl_restlet.js` 上传到同目录后，与Suitelet共用查询服务，网站不生成Excel；首次打开为空表单，多个查询条件由NS与Python后端校验。网站接入及真实两端对照状态见上方部署说明。

独立六表 MySQL 业务库已接入连接检查、按PL保存采购报关及本地查询。使用 `BUSINESS_MYSQL_*` 配置，与现有 `DATABASE_URL` 分开；不会自动建表或迁移。相关后端接口保留；“PL 单联查”前端入口已移除，当前核对页不提供本地保存操作。配置及验收见 [PL保存说明](../../docs/pl-storage.md) 和 [业务MySQL](../../docs/mysql/README.md#接入本地-mysql)。

后端保留记录查询、预览、确认创建或更新，以及持久任务和重复提交拦截；对应旧前端页面已移除。自动发票匹配、完整分页同步及其他业务RESTlet尚未接入；本次仅增加PL核对的共用脚本入口。

本版本按单个后端进程运行。真实 NS 与 MySQL 8.0 联调尚未完成；写入结果未知时必须人工核对，不能自动重试。切换数据库不会自动迁移已有任务，详细约束及恢复方法见 [后端文档](../../docs/python-backend.md)。
