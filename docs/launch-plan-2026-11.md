# 发票对账平台 11 月试用上线执行方案

状态：**待评审（2026-10-20 起草，2026-10-21 按业务答复更新 Q2、Q6、Q7、Q10）**。依据 2026-10 会议纪要整理，对照当前代码（`test` 分支 `17aaddb`）逐条标注现状。本文是方案，实施进度见第 5 节各任务的"进度"标注。

## 1. 结论

- 主线不变：以**报关单**为核心维度，打通"NS 同步 → 财务审核 → 开票通知 → 收票比对 → 归档"。系统已有这条链路，本轮以**补齐规则和配置**为主，不重写模块。
- 目标：本周完成细节调整与内部全流程测试，**11 月 4–5 日**小范围试用，跑通后全量推广；试用初期保留纸质打印，稳定后取消；不开发系统打印。
- 改动最大的三处：
  1. 共享盘按**月份 → CD 号 + 真实报关单号**重排，并增加回签合同批量上传；
  2. 开票通知改为**按供应商、每月固定日期合并推送**，并增加供应商**屏蔽推送**；
  3. 统一 **5 个业务状态**，各页面增加供应商筛选，工作台按状态分区展示。
- 时间很紧：建议按第 5 节把任务分为"上线必须（P0）"和"上线后迭代（P1/P2）"。NS 回写和自动审核风险较高，不建议压进 11 月 4 日的首批试用。

## 3. 关联点与改动重点

### 3.1 统一业务状态（影响最大的改动）

会议的 5 个状态是**报关单级别**的；系统里一张报关单可能拆成多个开票任务（按供应商×采购公司×币种）。建议由现有状态汇总得出，不另设可手改的状态：

| 业务状态   | 判定（全部由已有数据得出）                                                    |
| ---------- | ----------------------------------------------------------------------------- |
| 待审批     | 报关单未审核，或来源变化需重新审核                                            |
| 待通知开票 | 已审核，存在任务处于"待保存合同 / 待通知供应商"                               |
| 待核票     | 已通知（或免通知），存在任务处于"等待开票 / 部分收票"，或仍有待审核的比对建议 |
| 资料已回   | 全部任务已收齐发票（比对通过），但归档资料尚未到齐                            |
| 开票完成   | 全部任务完成，且报关单、发票、销售合同、回签合同、子采购合同全部归档          |

**已确认（Q10）：** 资料全部到齐才算完成。每张报关单在详情中列出五类资料的到齐情况，缺哪类一目了然；资料到齐与收票完成互不阻塞，任一未满足都停在对应状态。

### 3.3 申报幅度的数据来源（Q6 答复带来的新增）

- **销售单汇率**：报关行上有销售订单号（`sales_order_no`）。同步报关单时按销售订单读取 NS 销售单的汇率（同母采购单汇率的固定只读查询方式），保存到 source，不在页面临时请求 NS。
- **申报单价**：报关行的单价与币种（多为美元）× 销售单汇率 = 人民币申报单价。
- **采购单价**：取该报关行关联的子采购行单价；单位与报关行单位不同、或一条报关行对应多条子采购行时，按总价计算（见 Q6b），不在前端换算。
- 汇率或单价缺失时显示"待同步 / 无法计算"，不显示 0，也不参与价格异常判定。
- 销售单汇率参与报关单内容摘要：汇率变化后已审核的报关单需重新审核。

### 3.4 财务核对页层级显示（2026-10-21 新增）

业务希望报关单展开后"一级一级错开显示"。当前三层（报关单 → 报关行 → 子采购行）为了让数量、单位、金额上下对齐，第二、三层与第一层用了相同的列宽，层级不够明显。调整为：

- 第二层（报关行）相对第一层缩进一级，第三层（子采购行）再缩进一级，左侧用竖线标示从属关系，层级越深底色越浅；
- 数值列只在**同一层内**对齐，不再强制三层共用列宽；
- 新增的"申报幅度"列放在报关行最后，高于阈值或无法计算时用文字标注，不只靠颜色。
