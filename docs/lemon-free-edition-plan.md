# 柠檬云免费版账套接入方案

状态：3.4 open2 拉票修正已实施（2026-10-29）；版本并存改造未实施，待并行的 sync 页面改动提交后进行。归属 `sync` 模块（发现账套、拉票、批次）与 `invoice` 模块（保存，基本不改）。2026-10-29 依据用户提供的 open2 财务接口文档、免费版网页 `j6.ningmengyun.com` 当前公开脚本和现有代码整理；免费版已真实只读核实（见 2.1），尚未做入库保存验证。

## 1. 现状与差距

现有代码其实已经有“默认版”通道（即 open2 账套，等同免费版），但它被设计成与专业版**互斥**：

| 环节 | 现状 | 问题 |
| --- | --- | --- |
| 发现账套 | `LemonAccountService.authorized_accounts()`：专业版服务存在时只返回专业版；只有上游明确“没有专业版服务”才查 open2 `GetAccountSets` | 同时拥有专业版和免费版时，免费版账套永远不出现 |
| 账套标识 | 选择、批次、计划都只用 `asid` | 专业版与免费版是两套系统，`asid` 可能撞号；`edition` 只在内存列表里，没有持久化 |
| 拉票 | `_fetch` 按 `edition` 分派：专业版网页会话接口，否则 open2 `GetInvoice` | 分派逻辑可用；open2 `GetInvoice` 只做过 404 参数修复和无凭证探测，**没有用真实免费版账套拉到过票** |
| 商品明细 | 专业版有详情补全；open2 直接返回票头，`detail_status=pending` | 免费版票没有商品行，不会生成匹配建议 |
| 入库 | 命名空间 `open2:`／`professional:` 加 `SHA256(环境|asid)`，来源隔离 | 已满足，`invoice` 模块无需改 |

## 2. 接口依据（只读）

只使用以下只读接口。你提供的文档中的凭证、发票新增/修改/删除、科目、账套创建/删除/升级等写接口**一律不调用**。

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 用户令牌 | `POST /api/OAuth2/Token/GetSpecificUserToken` | 沿用现有绑定，与专业版共用 |
| 免费版账套 | `POST /api/Settings/AccountSet/GetAccountSets`（不带 `serviceId`） | 文档注明 `ServiceId` “免费版可以不传或者传 0”；2026-10-19 实测同一 Token 返回 2 个账套，带专业版服务 ID 仍返回这 2 个，推断即免费版账套，**须与免费版网页核对名称** |
| 免费版进项票 | `POST /api/Invoice/Invoice/GetInvoice?invoiceCategory=10080&...` | Bearer＋`asid` 请求头；现有实现已按文档补齐全部查询键 |
| 免费版商品明细 | open2 文档**没有**读取接口 | 见第 5 节 |

## 2.1 只读核实结果（2026-10-29）

在本机用已绑定手机号（182****3640）和 `.env.txt` 中的 open2 应用凭证执行只读查询；不写本地库，也不写柠檬云。

- **账套**：`GetAccountSets` 返回 2 个免费版账套：上海绎色数码科技有限公司（103793251）、上海亦络文化传媒有限公司（104240075）。专业版另有 6 个（200142891～200896951），两边 asid 不重叠。与网页显示及旧诊断脚本标注的版本一致。
- **进项票**：绎色 2026-10-01～10-28 读到 136 张，`Count=136`，分页 `page/rows` 生效，页间无重复；亦络同期 0 张。
- **合计行**：与专业版相同，最后一页末尾附一条合计（`InvoiceId=0`、`BusinessTypeText=合计`、无号码、无日期）；最后一页之后的空页仍只返回这一条合计。现有 open2 客户端会把它判成“编号缺失或分页重复”，**所以免费版拉票目前必然失败**。
- **金额**：`Amount`、`Tax` 为两位小数 Decimal；`AdValoremTaxTotals` 是文本，其中 61 张带千分位逗号（如 `1,234.00`），invoice 金额校验会拒收。去掉逗号后 136 张都满足“未税＋税＝价税合计”，逗号格式全部规范。
- **其他字段**：全部为数电发票，`Code` 为空，号码 20 位；`InvoiceType` 为 1060/1070/1130（普票、专票、铁路电子客票）；`IsInvalid` 有 0（133 张）和 2（红冲，3 张）；负金额 4 张；日期为 `YYYY-MM-DD`。业务类型含“采购固定资产”20 张，没有“采购支出”，其余为差旅、办公、修理等。
- **明细**：列表不含商品行字段，与文档一致。

## 3. 改造方案

### 3.1 账套发现：合并两个版本

`authorized_accounts()` 改为分别查询，再合并：

- 专业版：保持现有 `LemonProfessionalAccounts` 流程；没有专业版服务时结果为空列表。
- 免费版：调用 open2 `GetAccountSets`，每项标记 `edition="free"`。
- 一个版本查询失败时整体报错，不能只返回另一个版本的账套冒充完整列表（与现有“发现失败不回退”的规则一致）。
- 返回项新增 `key`（`pro:<asid>` 或 `free:<asid>`）、`edition` 和中文 `editionLabel`；前端只展示，不自行推断版本。

### 3.2 账套标识持久化（需要迁移 `0041_sync_lemon_edition`）

| 表／数据 | 变更 |
| --- | --- |
| `sync_lemon_bindings` | 新增 `selected_edition`（`professional/free`，可空） |
| `sync_lemon_runs` | 新增 `edition` 非空列；同一账套的运行中互斥改为按（版本，asid）判断 |
| `sync_lemon_plans.configuration`、`sync_runs` 配置快照 | `accountIds/excludedIds` 改为 `pro:123`／`free:456` 复合键 |

旧数据回填：现有记录均由“专业版优先”规则产生，而当前账号有专业版服务，因此回填为 `professional`；旧计划 JSON 中的纯数字 ID 读取时按 `pro:` 解释。迁移只加列和回填，不删除表或数据；回填前先统计受影响行数并写入迁移说明。

### 3.3 拉票与批次

- `LemonPullBody` 新增 `edition`，`asid` 格式校验不变；同一 `requestId` 改变版本视为参数变化，返回 409。
- `_fetch` 按请求里的版本重新发现账套，并要求（版本，asid）都匹配，不再用列表内 `edition` 猜测版本；撤权或版本变化时失败，不保存。
- `selected_accounts()`、分片、重试与汇总改用复合键；“全部账套”模式自动包含免费版，排除项也按复合键处理。
- 明细补拉（`targets`）仍只允许专业版，免费版返回明确原因。

### 3.4 open2 拉票修正（已实施）

- `invoice_client.invoices()`：按专业版的同一严格条件排除合计行（零编号、`BusinessTypeText=合计`、空代码/号码/日期）；其他缺编号的行仍报错。一页排除合计后没有发票即视为结束；各页 `Count` 必须一致，且最终张数等于 `Count`，否则整批不保存。
- `AdValoremTaxTotals` 文本只接受严格的千分位格式（`-?\d{1,3}(,\d{3})+\.\d{2}`）或普通两位小数，在 open2 适配层规范化后再交给 invoice；不改 invoice 的金额规则，也不接受其他展示格式。
- 测试用合成数据覆盖：末页合计、空页仅含合计、`Count` 变化、千分位金额、非法千分位。

### 3.5 前端

- 账套列表、单账套选择、批次表单、计划表单和批次详情显示“专业版／免费版”徽标（组件库 `Badge`，状态不只靠颜色）。
- 免费版账套旁提示“免费版暂无商品明细，入库后待补齐，不能自动生成匹配建议”（文案以后端 `reason` 为准）。
- 发票台账的账套筛选标签把“默认版”统一改为“免费版”（`invoice_account_service.py`）。

## 4. 实施步骤

1. ~~只读核实~~：已于 2026-10-29 完成，结果见 2.1。
2. 后端：先做 3.4 的 open2 拉票修正，再做合并发现、复合键、迁移 `0041`、拉票版本校验、批次/计划改造；补测试，覆盖两版本并存、撞号 asid、单版本失败不回退、旧计划兼容、版本变化 409。
3. 前端：徽标、提示、类型与表单提交复合键；补 `sync-background.test.mjs` 断言。
4. 隔离库验证：SQLite 全量测试，加上随机隔离 MySQL 库的同步/批次专项测试；浏览器使用假上游，检查两版本混合列表、桌面和小屏显示。
5. 部署：执行 `npm.cmd run db:upgrade` 升至 `0041`，然后重建并重启。先手动拉一个免费版账套的小日期范围，确认无误再让计划包含免费版账套。

## 5. 免费版商品明细（第二期，先调研）

匹配需要完整商品行，因此免费版票只能先入库，待补齐。可选来源：

| 方案 | 依据 | 风险 |
| --- | --- | --- |
| A. 免费版网页会话接口 | `j6` 与专业版网页同一套前端代码，API 域名为 `japi.ningmengyun.com`，同样有 `/api/Invoice/PurchasePagingList`、`/api/Invoice/PurchaseEntryList` 和按 `invoiceType/invoiceId` 读取详情的 `/api/Invoice`；2026-10-29 用户截图确认免费版账套（上海绎色数码科技有限公司）网页“进项发票 → 商品明细”能显示品名、金额、税率等商品行 | 非 open2 承诺接口；免费版的会话与 `appasid` 获取方式须实测（专业版经 `wbgate` 服务入口取得），官方升级可能失效 |
| B. open2 发票查验 `InvoiceApi/GetInfoByInput` | 返回 `dlist`（品名、规格、单位、数量、金额、税率、税额） | 实际走税局查验，可能计费或限流；需要代码、号码、金额或校验码、开票日期；全电发票支持情况未知，须先问柠檬云 |
| C. 维持待补齐 | 无额外依赖 | 免费版票只能人工比对 |

建议：第一期按 C 上线；第二期先按方案 A 做只读调研，复用专业版的明细解析和校验（字段为同一套前端模型）。方案 B 须柠檬云书面确认计费与全电支持后再评估。

## 6. 不变的约束

- 不调用任何写接口，不在柠檬云侧新增、修改或删除凭证、发票、账套。
- Token、Cookie、`appasid` 只存在于本次调用的内存中，不入库、不写日志、不返回浏览器。
- 外部读取在数据库事务之外；保存继续走 `LemonInvoicesFetched → invoice → LemonInvoicesStored` 事件链。
- 只支持柠檬云正式环境，与现有专业版限制一致。
