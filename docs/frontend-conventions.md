# 前端界面与交互统一规范

状态：新增/修改前端时适用的规范；已提取Button/Panel/JsonView、请求封装与设计变量；其余组件按需求提取。

## 1. 基准与职责

保留现有中文企业后台的导航与业务布局。当前正式入口加载shared基础样式与web/style.css；原型全局样式仅由DemoPage懒加载，页面之间已分离。原型算法仅限app/demo演示，后续迁移时用真实后端规则替换。

前端只负责表现和交互，所有校验、计算、业务权限、分页和统计来自后端。中文标签、字段错误与状态展示保持一致。重构阶段保持已接受的视觉基准；需要整站改版时作为独立任务处理。

## 2. 一份设计变量

已落地文件：`web/shared/styles/tokens.css`，已提取颜色、字体族、常用间距和圆角。字号、字重、阴影与浮层层级等其余变量在实际复用时继续从现有页面提取，建立统一命名，不凭每次 AI 的偏好重新选一套。

建议变量分组：`--color-*`、`--font-*`、`--space-*`、`--radius-*`、`--border-*`、`--shadow-*`、`--z-*`。状态采用成功、提示、待处理、失败、中性等语义变量。

变量从现有正式页面提取：主色#3156d9、文字#172033、次级文字#667085、画布#f4f6fa、控件圆角7px、面板圆角12px。新样式优先复用这些变量。

动态宽度等数据相关样式可以内联；固定颜色和重复尺寸使用变量或组件样式。页面 CSS 必须有作用域，不直接修改全站 button、table、input；必要的基础 reset 只维护一份。

## 3. 公共组件目录

目标目录：`web/shared/components/`。先从至少两个实际使用处提取，或在首次明确要统一的基础控件任务中建立，不批量生成空组件。

| 组件 | 统一的内容 |
| --- | --- |
| PageHeader | 标题、说明、主要操作的位置 |
| Button | 主次操作、危险操作、加载、禁用和尺寸 |
| DataTable / Pagination | 表头、行高、排序入口、分页和横向溢出 |
| FormField | 标签、输入、帮助、后端字段错误的布局 |
| StatusBadge | 状态文字、图标及语义颜色；不计算状态 |
| Modal / Drawer | 标题、内容、操作区、关闭和焦点行为 |
| LoadingState / EmptyState / ErrorState | 请求状态的统一呈现 |
| AmountText | 展示后端金额文本与对齐方式，不计算金额 |
| Feedback | 成功、失败和处理中反馈，绑定实际响应 |

组件公共参数用清晰的类型声明；避免增加几十个布尔开关把表格、卡片、表单硬塞进一个组件。业务特有的 CandidateList、InvoicePaper 等放回模块。

## 4. 页面组织

```text
web/modules/matching/
├── pages/MatchDetailPage.tsx       # 组合页面
├── components/CandidateList.tsx   # 候选呈现
├── hooks/useMatchEvaluation.ts    # 请求与UI状态
├── api.ts                        # API调用
└── README.md                     # 中文职责与接口说明
```

页面中不写 fetch 散落调用，统一经模块 api.ts 与 shared/api/http.ts。Hook 不藏金额算法和审批规则。正式页面不导入演示 fixtures；演示环境通过明确的模拟数据源适配，保留可见的来源说明。

新路由接入后才移除旧入口；同一个功能不能同时维护两套页面和两套状态逻辑。

## 5. 统一交互

| 场景 | 行为 |
| --- | --- |
| 首次加载 | 展示加载状态，不以空列表冒充没有数据 |
| 查询无结果 | 展示统一空状态；筛选条件仍可修改 |
| 请求失败 | 展示后端中文错误及安全重试入口；写入是否可重试由后端决定 |
| 表单错误 | 根据后端 fieldErrors 放到对应字段；全局错误放统一提示区 |
| 评估请求中 | 显示计算中，旧评估不继续作为可确认依据 |
| 快速切换选择 | 取消旧请求或忽略旧响应，不覆盖最新选择 |
| 业务不可操作 | 根据后端 allowed/reason 展示禁用原因，不由前端重算条件 |
| 提交成功 | 显示后端实际状态；入队只能称“已提交”，不能称“已写入成功” |
| 长任务 | 使用任务ID查询状态；刷新页面后可以恢复查看 |

不可访问的对象由后端拒绝；隐藏按钮只是展示效果。所有可操作控件有可读标签与键盘焦点，状态不能只用颜色表达。错误、加载状态应可被辅助技术感知。

## 6. 前端修改的验收

1. 检查当前正常数据页面及受影响的加载、空数据、失败状态；涉及弹窗或确认时覆盖对应交互。
2. 在主要桌面尺寸和较窄窗口下检查布局；表格允许容器内横向滚动，页面外壳不能异常溢出。
3. 检查其他复用该组件的页面，避免修改公共样式只让一页正确。
4. 执行构建和 lint；类型检查独立于 Vite 构建，已通过web/tsconfig.json和npm run typecheck独立执行。
5. 删除本次替代的重复样式、未使用组件和过时导入，说明引用核查结果。

构建通过只能证明对应构建检查通过。未打开页面、未做交互时如实记录，不能写“UI 验收通过”。视觉检查可以逐步增加关键页面基线，但更新基线前要查看差异，不能自动接受所有新截图。
