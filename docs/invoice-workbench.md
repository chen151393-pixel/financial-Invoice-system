# 发票工作台

正式入口 `/workbench`，同时作为默认首页。界面沿用 5197 示例的三张指标卡、待办表、关注事项和报表布局；复用系统登录、侧栏与设计变量，未嵌入示例网页或演示数据。

## 页面与接口

- 前端归属 `matching`：`pages/WorkbenchPage.tsx`、`hooks/useWorkbench.ts`、`components/Workbench*.tsx`；应用层 `WorkbenchWorkspacePage.tsx` 装配外壳、查询 Hook 和标题操作区。
- 后端归属 `matching`：`controller/workbench_controller.py`、`service/workbench_service.py`，跨模块只通过 `public.py` 读取 `review`、`source`、`task`、`invoice` 的事实。不新增表，不执行业务写入。
- `POST /api/matching/workbench/query`：返回指标、分页待办、当月任务进度、供应商排名和已开票趋势。
- `POST /api/matching/workbench/export`：返回 `filename`、UTF-8 CSV `content`、全量结果条数 `count`；沿用查询筛选与排序，不受页码限制。外部名称及单号防止被表格软件解释成公式。
- 两个接口都要求当前认证。参数为 `account`（NS 账套）、`keyword`（最长 120 字）、`kind`（all/review/matching/task）、`sort`（priority/oldest/newest）、`page`、`pageSize`（1–50）、`trendStart` / `trendEnd`（可选开票日期，YYYY-MM-DD；须成对填写，最多 92 天）。金额为十进制字符串，未知金额为 `null`。

## 业务状态分区（2026-10-23）

工作台顶部为五个业务状态卡片，按报关单计数，点击进入带同样筛选条件的财务核对或开票跟进列表：

| 业务状态 | 判定 |
| --- | --- |
| 待审批 | 报关单待财务审核，或来源变化需重新审核（review 判断，优先于任务状态） |
| 待通知开票 | 任务处于待保存子采购合同、待通知供应商 |
| 待核票 | 任务处于等待开票、部分收票 |
| 资料已回 | 任务发票已收齐、资料待补齐（documents_incomplete） |
| 开票完成 | 任务发票收齐且资料全部到齐（completed） |

报关单级别取其当前任务中**最慢**的阶段；审核通过但没有任何当前任务（供应商均关闭通知）为“无需开票”，不进分区与待办。

供应商与报关单创建日期筛选作用于分区与核对、开票待办；比对待办不按报关单日期筛选。

## 统计口径

| 区域 | 口径与范围 |
| --- | --- |
| 待财务核对 | 已出库（有真实报关单号且有关联子采购单）的有效报关单，包含待审核、来源或依据变化后的重审；已审核且依据未变的不计入。未出库的报关单自 2026-10-23 起拉取时即跳过，不入库（2026-10-22 版的 `counts.unshipped` 已取消；原 `blocked` 一并不再返回） |
| 待比对 / 复核 | 待人工审核建议，及已确认但有效性不为 valid 的分配；按发票 × 采购账套归并，一张票跨账套时分别计数 |
| 待开票任务 | 尚未完成、尚未被替代的当前任务，包含待合同、待通知、等待开票和部分收票 |
| 待办合计 | 上述待办事项数之和；同一业务可能出现在多个环节，不代表去重后的唯一单据数，不汇总不同类型的金额 |
| 待办金额 | 开票任务展示沿用跟进页逐行计算的待收含税金额；报关可能共享子采购行，比对可能存在相互竞争的建议，均进入详情核实金额，工作台不重复求和 |
| 本月任务完成进度 | 上海时区本月新建、当前未被替代的任务；已完成数 / 该批任务数。完成包括按差异结束，不等同于百分之百收票；旁列该批任务当前有效已收票金额，币种分别展示 |
| 供应商待收票金额 | 当前 NS 账套下有效未完成任务，按供应商身份、账套和币种分别汇总；每币种取前三。金额或币种不完整的供应商分组整体不纳入排名，并提示缺失组数 |
| 已开票金额趋势 | **全部发票账套**已导入且当前状态正常的进项发票，按票面开票日期统计价税合计，币种分开；不随 NS 账套、待办搜索或分类改变。默认展示上海时区本月 1 日至今天，按开票日期归属，不按导入时间截取；各币种仅展示有正常发票记录的日期，不为无票日补零，实际开票合计为零或金额未知的日期仍保留；可自选最多 92 天。响应 `trendStart/trendEnd/latestInvoiceDate` 标明实际范围；本月无发票时显示空态并提示库内最新开票日期，未导入的外部发票不在范围内 |

超期信息与计划开票趋势不展示。当前只有一个 NS 正式账套，页面不提供账套选择，也不重复显示账套编号；接口保留账套筛选能力。关键词、分类、排序只作用于待办。比对与任务点击进入独立详情；核对携带报关编号和账套进入财务核对页面。优先排序为阻塞核对及待复核分配、待比对建议、普通核对、开票跟进，同优先级按首次入库时间和稳定标识排序。

查询在同一数据库连接与只读事务中完成，MySQL 使用 REPEATABLE READ 固定快照。当前版本在后端读取轻量索引后合并、筛选、排序及分页，未限制统计为前 N 条，也不在浏览器处理全量数据。大数据量场景需要进一步压测和查询优化。
