# 子采购订单、报关单与发票存储执行方案

更新日期：2026-09-14。已交付独立 MySQL 建表 SQL、独立业务库连接配置和只读检查接口；正式本地MySQL已连接。采购报关按PL保存、本地查询及页面操作已实现，并使用假NS与隔离MySQL验收；真实字段映射仍待配置。外部发票接入及固定15列跨行汇总尚待实现。未迁移或修改现有应用数据库。

## 1. 当前范围

按用户最新要求：采购订单和报关单只接 NS，发票接外部平台或文件。保留三类主表和各自明细共六张表，来源信息放入各自主表。暂不建设多来源映射、同步任务表、同步占用表和拼表大表，后续有实际需求时再扩展。

结构、字段含义、唯一键及执行方式以 [MySQL 说明](mysql/README.md) 和 [建表 SQL](mysql/business-schema.sql) 为准。原九表方案及活动来源切换设计已由本版替代。

## 3. 存储身份

- 本地自增主键不依赖 NS。NS 两类主表以租户、NS账户、内部ID去重，采购到报关通过解析后的本地主键关联。
- 外部发票以租户、平台、账户及外部ID去重；无ID时使用稳定导入键。缺少稳定身份先核实，不能每次生成新键制造重复单据。
- 每张单据仅保留一个来源的当前快照；明细唯一键为租户、父单ID、稳定来源行键。
- 全部主从关联检查租户；采购报关关联还检查NS账户。公司标识保留引用类型及ID，同一账户中比较，不按同名公司强行归组。
- 主表保存原始JSON和同步时间。源引用尚未解析时保留在原始JSON，本地外键允许空，不把NS内部ID直接写入本地外键。

## 4. 保存流程（待实现）

1. 完整读取单头和明细，检查分页结束、稳定行键、精度和币种。
2. 外部请求完成后进入短事务，定位主表，再保存单头和明细。
3. 完整读取成功后才能停用来源已移除的行；失败不得清空旧数据。
4. 原始快照和主从数据一起提交，记录成功时间。失败保留最后完整快照并提示。
5. 同单据从读取到保存先串行执行；仅靠唯一键或保存时行锁无法避免过期快照覆盖。可靠来源版本可用于拒绝旧版本。

不在本期草案里预建任务调度服务。批量操作可以逐单提交并返回结果，但不能因此声称已有持久进度、断点续传或崩溃恢复。现有 NS 回写预览、锁、审计与结果未知处理完全保留。

## 6. 本地查询与页面（待实现）

保留现有实时 `/api/ns/pl-lookup` 契约。本地入口建议 `GET /api/business/pl-documents`，发票列表建议 `GET /api/invoices`，均由后端授权、搜索和分页。已实现本地PL查询，当前路由为 `POST /api/business/pl-documents/query`；发票接口仍待实现。

采购、报关各自关联主表后按租户、NS账户、PL及公司引用归组；展示为上方报关集合、下方采购集合。查询检查主从有效状态与最后完整同步时间，刷新失败的旧快照可显示并提示。发票没有明确采购分配关系时保持独立列表。

### 6.1 用户确认的拼表版式（待实现）

固定 15 列，同组报关数据在上、采购数据在下。表1指采购货品行，表2指报关明细及其单头。不把两侧字段随意互相补空，也不把原始金额混合求和。最终业务表不常驻显示技术内部 ID 或额外的“关联组”列，来源可通过行标记和详情入口识别。

| 最终列 | 上方报关行 | 下方采购行 |
| --- | --- | --- |
| 报关单号 | 表2真实报关单号 | 留空 |
| 申报日期 | 表2申报日期 | 留空 |
| 关联PL单号 | 表2 Packing NO. | 表1关联PL单号 |
| 销售单号 | 表2销售订单编号 | 留空 |
| 母采购单号 | 留空 | 表1关联母采购单号最大值，汇总范围待明确 |
| 子采购单号 | 留空 | 表1 ID 显示字段，不是数据库主键 |
| 货源地 | 表2境内货源地 | 留空 |
| 供应商 | 留空 | 表1供应商 |
| 申报公司抬头 | 表2明细公司抬头 | 表1公司抬头 |
| 开票品名 | 表2报关品名 | 表1报关品名 |
| 型号 | 表2规格 | 留空 |
| 数量 | 表2数量 | 表1数量 |
| 单位 | 表2单位 | 表1报关单位 |
| 含税单价 | 按图示为总金额÷数量；跨行共享方式待确认 | 同左，不能默认使用另一侧不兼容的单位 |
| 总金额 | 留空 | 表1对应范围内采购金额之和 |

图中含税单价为上下跨行单元格；实际使用哪一侧数量作为分母，以及金额汇总到商品还是整个分组，仍需业务确认。数量为零或缺失时不计算；数量或单位不一致时不能把同一单价解释为两侧均适用。

同一 PL＋公司有多条商品时，先保留上方报关行集合和下方采购行集合，不做笛卡尔连接、不按数组位置强制两两配对。若要求每个商品形成恰好上下两行，必须补充商品对应或汇总规则。数量不同单位不能相加，金额必须带币种。

现有实时查询的取数链路为：PL → 子采购订单 → 采购货品行；再由采购单关联报关单 ID 去重读取报关单及明细，排除其他 PL。当前代码仍是通用来源列表，不代表本节固定 15 列和跨行单价已经实现；真实可用性还取决于字段映射与联调。

采购、报关和发票的金额不混合求和；单位不同不比较数量。发票没有明确分配关系时只进入独立发票列表，不强行塞进 PL 结果。
