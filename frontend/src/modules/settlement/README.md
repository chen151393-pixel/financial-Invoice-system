# 结汇对账页面（settlement）

侧栏“财务”分组的“结汇对账”下有六个子页面，共用页面权限代码 `settlement`，默认入口为收汇总览，路径在 `app/paths.ts`：

| 子页面       | 路由                        | 内容                                                                                                       |
| ------------ | --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 收汇总览     | `/settlement/overview`      | 三项累计合计及香港中转 / 直接收汇拆分、客户收汇明细；只读，不重复计入香港汇回                              |
| 报关应收汇   | `/settlement`               | 按境外收货人汇总与逐张报关单查看已收、未收、结汇阶段、账龄与资料状态；只读，办理入口跳到香港批次或客户总账 |
| 银行收汇明细 | `/settlement/bank-receipts` | 导入银行 .xlsx、查询收汇记录、实际客户与三方代付标记                                                       |
| 香港中转批次 | `/settlement/hk-transit`    | 待登记回款勾选建批次；已建批次跟进资料与汇回结汇                                                           |
| 直接收汇明细 | `/settlement/direct`        | 非香港中转的总账：按境外收货人、收款人和币种汇总差额，可展开查看出口与收汇流水                             |
| 合同抬头     | `/settlement/parties`       | 销售合同买卖双方的名称、地址、电话与印章                                                                   |

直接收汇不再建批次，原“直接收汇批次”列表已由“直接收汇明细”取代（2026-11-18）。

2026-11-19：报关应收汇首张卡片展示后端 `combinedTotals` 的同币种总应收（香港中转 + 直接收汇），其余路径分项保留。银行收汇顶部按后端 `featuredCompany` 展示上海绎色数码科技有限公司、上海绎视数码科技有限公司、上海毅鑫实业有限公司三家收款抬头，各币种单独出卡、无记录补零；其他抬头单独列出。两处合计均按全部筛选结果计算，不按当前页加总。

后端规则见[后端 settlement 模块](../../../../backend/modules/settlement/README.md)。

报关应收汇展示（2026-11-19）：原上下排列的客户汇总、报关单明细合并到“应收报关单”区域，通过左侧“按客户汇总”和右侧“报关单明细”切换，默认客户汇总。两个视图共用查询条件和一次候选查询结果；切换不重发接口请求，已填写未提交的筛选也保留。`view`、客户、报关单号、回款路径、出口日期范围保存在 URL；重置只清空查询条件，保留当前视图。汇总仍使用后端全量 `consignees`，明细截断时单独说明展示范围。香港中转待登记页面不展示这组页签，保留勾选与建批次流程。

回款登记弹窗（2026-11-19）：复用统一 `Field`、`Dialog`、`Alert` 和主按钮；回款信息与收款凭证分区，付款方占整行，小屏单列。金额以输入字符串原样提交，千分位和精度由后端校验；通过公共 `HttpError.fieldErrors` 在对应金额字段显示错误并聚焦。失败保留输入，提交期间禁用编辑与关闭，并防止重复提交。

收汇总览调用 `POST /api/settlement/overview/query`，币种、收货人和分页条件保存在 URL。金额与合计全部由后端提供，合计覆盖全部筛选结果；不同币种分别展示。未收 = 应收 − 客户实收，负数表示超收，手续费单列且不并入实收。客户明细可进入按收货人筛选的香港批次（含已结汇）或直接收汇列表。香港到账只反映客户收款，不能据此判断已汇回或已结汇。报关应收汇保留查询展示，回款登记统一在香港中转批次办理。

文件只读取字节后以 base64 提交，格式校验、提单解析、资料齐全度都在后端。前端不计算金额与差额，不判断能否操作：核对结果、状态文案和 `allowed/reason` 全部来自后端。报关单能否选入批次按后端返回的 `handling`（`batch` 建批次 / `ledger` 进总账）与 `blockedReason` 展示；直接收汇明细的总账差额、状态与合计也全部来自后端。

收汇总览布局：顶部三张累计金额卡，随后为币种 / 境外收货人查询、收汇路径汇总和客户未收汇明细。路径表直接使用接口 `totals[].routes` 的全量结果，不对客户分页数据重新汇总；手续费继续在客户明细单列展示。未接入的统计主体及截止日期筛选不展示。

2026-11-19 回款入口迁移：报关应收汇移除勾选、到账组合推荐及登记弹窗，保留只读报关明细与香港登记跳转。香港中转 `/settlement/hk-transit?tab=receipts` 为待登记回款，默认地址为已建批次；支持携带 `consignee`。待登记查询固定 `route=hk_transit`、`batchStatus=unbatched`，筛选在后端完成；金额或币制有问题的单据仍显示不可选原因。建好批次后切换到香港已收阶段；批次默认仅显示节点进度，资料由用户主动展开。`CandidateTable` 只在传入 selection 时显示选择列，`CandidatePanel` 复用查询和登记流程。

## 直接收汇办理资料（2026-11-19）

`DirectDocumentsPanel.tsx` 展示后端资料状态、筛选与分页，选中报关单后复用 `BatchDocuments.tsx` 上传提单、人工核对、生成销售合同并下载资料包。该组件的 `target` 数字代表香港批次，字符串代表直接收汇报关单，API 按命名空间分流。资料操作不创建直接收款批次，不改变总账金额。

2026-11-19 合同双方取值：`ContractGenerateForm` 按每个出口合同展示“买方（境外收货人）／卖方（NS 申报抬头）”及关联报关单，取消卖方下拉，不提交手选卖方 ID。资料合同表也展示双方。取值、来源冲突和能否生成均由后端返回；英文地址、印章等仍在“合同抬头”维护。

2026-11-19 直接收汇金额卡片固定在“客户总账／报关资料”切换上方。两页签共享当前总账查询结果；切换页签、定位资料不重新加载卡片，总账筛选表单在切换时保留。客户 URL 范围改变时重新加载对应客户数据。

## 香港中转工作区（2026-11-20）

`/settlement/hk-transit` 采用“进行中 / 待登记回款 / 香港已收·办资料 / 资料已出·待汇回 / 已结汇”五个阶段入口。待登记报关单与已建批次同页展示；办理资料和登记汇回跳转独立批次页 `/settlement/hk-transit/batches/:batchId`，复用 `BatchWorkspace` 与 `BatchDocuments`；原详情弹窗也复用该工作区。旧 `tab=receipts` 链接映射待登记阶段，`batchNo` 链接映射关键字并包含终态。

批次卡片默认展示流程节点，“收起/展开流程”只控制节点进度；“办理资料”“登记汇回”进入独立批次页，列表不再内嵌资料。通过路由状态保留香港列表筛选与页码，面包屑返回原范围；直接打开或刷新地址也可加载。批次读取失败可重试。

独立批次页按确认后的 HTML 示例组合现有 `Card/CardHeader/Badge/Tabs/DataTable/Field/Button`：顶部为真实批次概览，只保留“资料办理／汇回登记”两个页签；没有“批次信息”页签和完整报关单信息区。资料办理按提单、销售合同、报关单原件和办理操作分卡，复用 `BatchDocuments` 的 `standalone` 展示模式；去掉顶部未齐汇总提示，保留各行真实状态、生成或提交拒绝原因与错误。现有直接收汇资料区继续使用默认展示。

页签通过 `mode=remit` 保存在地址中。切换页签只隐藏内容，不卸载资料或汇回表单；上传、修改、移除提单与生成合同只更新当前资料和批次许可，不重载列表或收起。确认资料已出后重新读取资料编辑许可。汇回日期、金额、手续费、流水号均由人工填写并原样提交现有 `remittance` 接口，前端不计算金额或判定对平；按钮按后端 `allowed/reason` 展示，失败保留输入且不自动重试，成功展示接口返回的汇回与结汇状态。旧批次弹窗复用相同工作区，上传及提交期间禁止关闭（2026-11-27）。

阶段统计、冻结金额、等待天数、资料标记、操作许可及分页来自 `hk-workbench/query`；搜索覆盖批次号、报关单/CD 和流水号。筛选、阶段与分页保存在 URL；查询切换取消旧请求，并只展示本次请求对应的结果。登记入口跳转独立人工登记页 `/settlement/hk-transit/register`，新页面严格对平才允许提交，详情见“香港回款人工登记”。

`hk-workbench/export` 导出当前筛选范围的完整 CSV，不限当前页。已结汇为累计口径，待汇回超期提示复用原有 30 天规则。资料包下载采用后端许可；原件未归档只提示。该改动只涉及香港中转展示，直接收汇仍使用原总账和报关资料。

## 报关单结汇详情（2026-11-20）

在报关应收汇、香港待登记报关单、批次明细及直接收汇资料列表点击报关单号，打开统一右侧详情。URL 的 `detail` 保存当前报关单，保留背景页筛选；关闭、Escape、浏览器后退可返回列表。侧栏复用 `Dialog placement="right"`，窄屏全宽；资料只读，办理跳回所属批次或单票资料页。

详情显示后端流程进度、香港批次核对或直接收汇 FIFO 流水依据、本单高亮、三方付款人、归档原件、覆盖本单的提单及销售订单；缺项折叠显示，与非阻断提醒分开。直接收汇资料已接入真实单票组与合并后继关系，资料归属跟随所在组；从本单详情进入对应资料组办理。加载、失败、重试与切换请求取消独立处理；金额不在前端计算。

### 单票资料组与合并办理（2026-11-20）

“直接收汇明细”只保留一排“客户总账／报关资料／多票资料组”切换，金额卡片仍固定在其上方。“报关资料”按单票列出，首次办理时通过 `/single` 确保建立真实单票组，再进入独立的 `/settlement/direct/document-groups/:groupId`。合并从单票资料发起，进入 `/settlement/direct/document-groups/merge?declarationNo=…`；旧 `groupId`、`declarationNo` 查询链接仍可跳转到新资料页。

`DirectDocumentMergeWorkspace` 保留本单、跨页选择，展示后端返回的条件、金额、共用提单与合并后合同预览；确认提交 UUID 与不可变预览摘要，过期时重新核对，不沿用旧结果。`DirectDocumentGroupsPanel` 只查询多票组；`DirectDocumentGroupWorkspace` 将组内报关原件与提单并排展示，复用 `BatchDocuments` 上传共享提单、核对覆盖范围、按卖方和销售订单生成合同及下载资料包。不同卖方的同号合同用后端 `key` 区分，保留原合同编号。报关详情仅展示该单覆盖的资料，并链接到所在组。

已有单票资料继续可用；归组后列表显示组号并进入组内统一办理。页顶金额卡片继续位于客户总账／报关资料切换上方，建组不更改总账金额。接口与资料归属规则见后端模块文档的“直接收汇资料组”。

## 结汇进度图（2026-11-20）

收汇总览新增 `SettlementProgressPanel`：单独加载、失败重试，客户/币种与总览筛选同步，刷新同时更新；失败不阻断原有总览金额与客户表。按币种显示已结汇报关金额占比，以及香港中转、直接收汇各自的阶段横向条形，同币种采用后端共同刻度。每行直接显示金额、票数，部分收汇注明已收和未收，不依赖悬停和图例对照。零值保留文字、不画假色条，阶段无单据时不可下钻。

点击阶段跳转报关单明细，URL 保留收货人、路径、阶段和币种。桌面两列、小屏上下排列；使用公共 Card、Badge、Progress，金额和几何宽度由后端给出，无新增图表依赖。Figma 中使用明确标注的示例金额，本地页面读取真实接口。

## 总览账龄与待办（2026-11-20）

`overview/query` 新增 `insights` 和 `asOf`，复用完整报关应收汇快照；按币种返回未结汇账龄、待处理事项和已结汇报关金额。账龄从出口日期起算，金额为尚未结汇报关单的完整报关金额；缺出口日期单独提示，仍计入未结汇合计。已在香港到账但尚未汇回的报关单仍属于未结汇。

香港超期沿用到账后超过 30 天的规则；补资料只统计资料缺失或合同失效的已收香港批次；直接催收按逐单 FIFO 未收推算。待办跳转现有批次、登记或客户总账页面，保留客户范围；报关单明细同时保留币种筛选，其他工作区按币种分别展示，不执行写操作。客户表按未收差额排序，进度宽度封顶 100%，实际百分比保留超收；客户实收仍取实际到账、手续费单列，不用逐单推算覆盖原总览口径。分页只影响客户表，账龄和待办始终覆盖全部筛选结果。

## 香港回款人工登记（2026-11-20）

从香港中转勾选报关单后进入独立登记页；左侧展示选单、移除和返回补选，以及日期、到账金额、手续费、付款方、收款账户、流水号与备注；右侧展示后端核对结果、差额和提交原因。所有流水字段人工填写；银行水单 PDF 只作为可选附件随提交保存，不做文字提取或 OCR。历史收款账户可选择，也可直接填写实际账户。

`receipt-preview` 返回同一客户、同一币种、有效选单、日期、金额对平和手续费预警；预警提醒不阻断对平提交。输入更新和请求取消期间禁用提交。金额保持字符串传给后端，不在前端计算。补选时通过内存草稿保留手工内容与附件，刷新页面后草稿不保留；URL 仅携带报关单号和幂等请求号。提交成功返回对应批次，批次资料区可查看留存水单。布局沿用公共 Card、Field、Button、Badge，窄屏上下排列。

销售订单口径确认（2026-11-20）：业务确认海关回执的“出口合同号”即销售订单号。页面统一称“销售订单”，生成仍沿用该回执编号；同订单同卖方合并，不同订单或不同卖方分别生成。接口和数据库兼容保留 contractNo / contract_no，不改用另查的 NS 销售订单金额，也不改变金额、签订日期和买卖方取值。

结汇资料区的缺项与提醒默认折叠，保留齐全度标题和待处理数量；点击“展开明细”查看，再次点击收起。香港批次与直接资料组共用这一展示方式，后端校验和办理许可保持原规则。

未生成销售合同的 `planned` 同步返回 `contractDate`、`portOfLoading` 和 `portOfDestination`。列表显示对应提单当前口岸与拟定签订日期（对应报关单最早出口日期减配置提前天数），不受合同抬头缺失影响；未生成日期标注“拟”，提单修改或移除后重新读取当前依据。已有合同仍展示生成文件记录的日期和口岸，变更依据后保留“需重新生成”状态，不把新计划冒充旧 PDF 内容。

合同抬头页面（2026-11-20）：列表复用 Card、DataTable 和 Badge，按名称、地址与联系方式分配列宽，地址和电话分行展示。新增／修改共用 PartyDialog，复用 Dialog、Field、Button 与 Alert；匹配名称、英文名称整行，地址使用多行输入，小屏单列。错误来自后端，保留表单值并关联到对应字段；保存期间禁用编辑与关闭。买方匹配海关回执境外收货人，卖方匹配 NS 申报抬头，维护提示与实际合同匹配规则一致。

合同抬头操作区统一使用 Button 的 sm 紧凑尺寸，不带图标：新增使用主按钮，修改与上传／更换印章使用同宽次要按钮。操作列固定留足空间，按钮保持同一行；小窗口通过表格自身横向滚动访问操作。

## 资料组恢复与合并重试（2026-11-20）

资料组来源发生客户或币种更正时，按后端 `updateSource.allowed/reason` 展示“核对并更新来源”。`DocumentGroupBasisDialog` 展示更新前后客户/币种、当前完整组金额与成员数；确认仅提交预览摘要。保存后刷新组和资料，仍由后端判断原合同是否失效。已无有效依据或组内跨客户/币种不能通过该操作继续办理。

合并遇到连接中断、异常响应或服务端错误时，先按原 requestId 查询结果；已提交则打开对应组。暂未确认时保留原范围、提单选择、预览和幂等请求，锁定选择修改，显示“合并结果待确认／按原请求重试”，不以重新预览的占用状态阻断幂等恢复。明确的参数或版本冲突返回后，才解除该等待状态并重新核对。组件卸载后不执行迟到的页面跳转。

仅剩本单时也展示“当前条件下没有其他报关单”，与本单固定选中分开说明。原生文件选择、编辑保存和移除确认保持原流程。
