# 结汇对账页面（settlement）

侧栏“财务”分组的“结汇对账”下有六个子页面，共用页面权限代码 `settlement`，默认入口为收汇总览，路径在 `app/paths.ts`：

| 子页面       | 路由                        | 内容                                                                       |
| ------------ | --------------------------- | -------------------------------------------------------------------------- |
| 收汇总览     | `/settlement/overview`       | 三项累计合计及香港中转 / 直接收汇拆分、客户收汇明细；只读，不重复计入香港汇回 |
| 报关应收汇   | `/settlement`               | 按境外收货人汇总与逐张报关单查看已收、未收、结汇阶段、账龄与资料状态；只读，办理入口跳到香港批次或客户总账 |
| 银行收汇明细 | `/settlement/bank-receipts` | 导入银行 .xlsx、查询收汇记录、实际客户与三方代付标记 |
| 香港中转批次 | `/settlement/hk-transit`    | 待登记回款勾选建批次；已建批次跟进资料与汇回结汇                         |
| 直接收汇明细 | `/settlement/direct`        | 非香港中转的总账：按境外收货人、收款人和币种汇总差额，可展开查看出口与收汇流水             |
| 合同抬头     | `/settlement/parties`       | 销售合同买卖双方的名称、地址、电话与印章                                   |

直接收汇不再建批次，原“直接收汇批次”列表已由“直接收汇明细”取代（2026-11-18）。

2026-11-19：报关应收汇首张卡片展示后端 `combinedTotals` 的同币种总应收（香港中转 + 直接收汇），其余路径分项保留。银行收汇顶部按后端 `featuredCompany` 展示上海绎色数码科技有限公司、上海绎视数码科技有限公司、上海毅鑫实业有限公司三家收款抬头，各币种单独出卡、无记录补零；其他抬头单独列出。两处合计均按全部筛选结果计算，不按当前页加总。

后端规则见[后端 settlement 模块](../../../../backend/modules/settlement/README.md)。

报关应收汇展示（2026-11-19）：原上下排列的客户汇总、报关单明细合并到“应收报关单”区域，通过左侧“按客户汇总”和右侧“报关单明细”切换，默认客户汇总。两个视图共用查询条件和一次候选查询结果；切换不重发接口请求，已填写未提交的筛选也保留。`view`、客户、报关单号、回款路径、出口日期范围保存在 URL；重置只清空查询条件，保留当前视图。汇总仍使用后端全量 `consignees`，明细截断时单独说明展示范围。香港中转待登记页面不展示这组页签，保留勾选与建批次流程。

回款登记弹窗（2026-11-19）：复用统一 `Field`、`Dialog`、`Alert` 和主按钮；回款信息与收款凭证分区，付款方占整行，小屏单列。金额以输入字符串原样提交，千分位和精度由后端校验；通过公共 `HttpError.fieldErrors` 在对应金额字段显示错误并聚焦。失败保留输入，提交期间禁用编辑与关闭，并防止重复提交。

收汇总览调用 `POST /api/settlement/overview/query`，币种、收货人和分页条件保存在 URL。金额与合计全部由后端提供，合计覆盖全部筛选结果；不同币种分别展示。未收 = 应收 − 客户实收，负数表示超收，手续费单列且不并入实收。客户明细可进入按收货人筛选的香港批次（含已结汇）或直接收汇列表。香港到账只反映客户收款，不能据此判断已汇回或已结汇。报关应收汇保留查询展示，回款登记统一在香港中转批次办理。

| 文件                                                                | 作用                                                                                                     |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |

| `pages/SettlementBatchesPage.tsx`                                   | 批次列表（目前只挂载香港中转；状态筛选按路径给出）                                                       |
| `pages/SettlementBankReceiptsPage.tsx`、`components/BankReceiptImportDialog.tsx` | 银行流水导入、导入结果、收汇抬头汇总、列表与筛选 |
| `pages/SettlementLedgerPage.tsx`、`components/LedgerGroupTable.tsx` | 直接收汇明细：按境外收货人、收款人和币种汇总，可展开查看流水、单据编号及每笔后的累计余额 |
| `components/ReceivablePanel.tsx`、`ReceivableTable.tsx`、`receivable-tones.ts` | 报关应收汇双视图、共享查询与结汇状态页签；逐单收款进度、资料状态、结汇状态与下一步入口；阶段 / 资料状态到徽标颜色的映射 |
| `components/CandidatePanel.tsx`、`CandidateTable.tsx`               | 香港中转待登记回款：查询、勾选、到账组合推荐和登记建批次                                                  |
| `components/ReceivableStats.tsx`、`ConsigneeSummary.tsx`            | 应收汇概况卡（总应收、两条路径、待登记回款、直接收汇待收）；按境外收货人汇总表（阶段分布、应收 / 已收 / 未收、资料、处理方式） |
| `components/CreateBatchDialog.tsx`                                  | 登记回款建批次（到账、手续费、付款方、账户、流水号）                                                     |
| `components/BatchDetailDialog.tsx`                                  | 批次详情：到账 / 汇回核对、确认资料已出、登记汇回、确认结汇、作废                                        |
| `components/BatchDocuments.tsx`                                     | 香港中转批次详情中的资料区：提单上传 / 修改 / 移除、销售合同（形式发票）生成、报关单归档状态、资料包下载 |
| `components/BillEditForm.tsx`、`ContractGenerateForm.tsx`           | 提单字段人工确认表单；生成销售合同前只读核对双方来源并确认条款的表单                                                 |
| `pages/SettlementPartiesPage.tsx`、`components/PartyDialog.tsx`     | 合同抬头列表、新增 / 修改、印章上传                                                                      |
| `api.ts`、`types.ts`                                                | 接口与类型，金额为十进制字符串                                                                           |

文件只读取字节后以 base64 提交，格式校验、提单解析、资料齐全度都在后端。前端不计算金额与差额，不判断能否操作：核对结果、状态文案和 `allowed/reason` 全部来自后端。报关单能否选入批次按后端返回的 `handling`（`batch` 建批次 / `ledger` 进总账）与 `blockedReason` 展示；直接收汇明细的总账差额、状态与合计也全部来自后端。

收汇总览布局：顶部三张累计金额卡，随后为币种 / 境外收货人查询、收汇路径汇总和客户未收汇明细。路径表直接使用接口 `totals[].routes` 的全量结果，不对客户分页数据重新汇总；手续费继续在客户明细单列展示。未接入的统计主体及截止日期筛选不展示。


2026-11-19 回款入口迁移：报关应收汇移除勾选、到账组合推荐及登记弹窗，保留只读报关明细与香港登记跳转。香港中转 `/settlement/hk-transit?tab=receipts` 为待登记回款，默认地址为已建批次；支持携带 `consignee`。待登记查询固定 `route=hk_transit`、`batchStatus=unbatched`，筛选在后端完成；金额或币制有问题的单据仍显示不可选原因。建好批次立即打开详情，关闭后切到已建批次。`CandidateTable` 只在传入 selection 时显示选择列，`CandidatePanel` 复用查询和登记流程。


## 直接收汇办理资料（2026-11-19）

保留直接收汇总账，新增“客户总账 / 报关资料”页签。`/settlement/direct?tab=documents` 为资料清单，`consignee` 可限定客户，`declarationNo` 可直接定位资料。客户行“报关资料”、出口流水行“办理资料”均跳转到同一入口。

`DirectDocumentsPanel.tsx` 展示后端资料状态、筛选与分页，选中报关单后复用 `BatchDocuments.tsx` 上传提单、人工核对、生成销售合同并下载资料包。该组件的 `target` 数字代表香港批次，字符串代表直接收汇报关单，API 按命名空间分流。资料操作不创建直接收款批次，不改变总账金额。


2026-11-19 合同双方取值：`ContractGenerateForm` 按每个出口合同展示“买方（境外收货人）／卖方（NS 申报抬头）”及关联报关单，取消卖方下拉，不提交手选卖方 ID。资料合同表也展示双方。取值、来源冲突和能否生成均由后端返回；英文地址、印章等仍在“合同抬头”维护。

## 报关应收汇逐单状态（2026-11-20）

报关应收汇改用 `POST /api/settlement/receivables/query`（`ReceivablePanel`），香港待登记页继续用 `candidates/query`（`CandidatePanel` 只保留登记流程，`CandidateTable` 必须传入勾选）。

- 概况卡、客户汇总、逐单已收 / 未收、收款进度宽度与百分比文本、阶段计数、资料状态全部来自后端，前端不加总、不算百分比。
- 客户汇总：境外收货人下列出各结汇阶段票数与未结汇最久天数；“应收 / 已收 / 未收”一列带进度条，直接收汇标“推算”并显示客户超收；资料列显示待处理票数与说明；香港中转有待登记时入口为“去登记回款”，否则为香港中转批次；直接收汇入口为客户总账。“看 N 票明细”切到报关单明细并按该客户筛选。
- 报关单明细：上方按结汇状态页签筛选（`stage` 保存在 URL，`alert` 为需要关注），列表按等待天数从长到短；每行给出下一步：去登记回款、去批次办资料 / 登记汇回（链接 `/settlement/hk-transit?batchNo=…`，批次列表据此筛选并包含已结汇）、客户总账与留存资料。
