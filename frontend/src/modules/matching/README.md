# 发票比对页面

架构 v2 第 4d 步重建。后端规则见[后端 matching 模块](../../../../backend/modules/matching/README.md)。

| 路径                   | 页面                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| `/matching`            | `pages/MatchingQueuePage.tsx`：待审核建议队列，按置信度筛选，批量通过高置信度且无需说明的建议                  |
| `/matching/:invoiceId` | `pages/MatchingInvoicePage.tsx`：左侧发票行导航、右侧选中行详情；手动关联、删除关联、通过 / 驳回，重新生成建议 |

旧地址 `/matching?invoiceId=…` 跳转到 `/matching/…`。外壳在 `app/MatchingWorkspacePage.tsx`，侧栏菜单名为"发票比对"。

详情页按整张发票票面、左右分栏逐项核对的顺序展示。2026-10-29 按页面简化要求移除顶部“NS 回写准备”（含“重新检查整票”）及底部“整张子采购单匹配”表单，并删除这两个无其他调用方的组件。保留待处理比对切换、单条审核、候选查询及手动关联；NS 回写独立页面和后端整单匹配接口不变。

## 规则

- 能否通过、为什么不能通过、需要填写说明的原因都来自后端 `confirm` 与 `noteReasons`；提交时后端重新校验，失败显示真实原因并保留输入，不自动重试。
- 只读查询遇到会话失效时恢复一次；写操作不自动重试。人工分配沿用同一请求标识，结果不明时重试不会重复分配。
- 通过、取消后显示后端返回的最新比对视图；任务收票进度在"开票跟进"中查看。
- 选中行的分配按后端状态分三组展示：已关联（已通过且依据有效）、待处理（待审核建议或需重新核实）、已驳回或已取消。“删除关联”调用后端取消分配接口：原因必填、记录保留可追溯、收票进度由后端回退；能否删除只看 `cancel.allowed`。
- 审核队列由后端按整票支持置信度、供应商、开票日期与异常筛选；没有关键词搜索，页面不在前端过滤当前页冒充搜索。

## 发票工作台

正式入口 /workbench（默认首页），复用本模块只读汇总接口。2026-10-27 起按设计稿依次为关键指标（`WorkbenchKpis`）、业务流程漏斗（`WorkbenchMetrics`）、应开与已收票金额趋势与节点分布（`WorkbenchReceipts`、`WorkbenchNodes`）、供应商待收票排行与比对队列（`WorkbenchSuppliers`、`WorkbenchQueue`）、优先处理（`WorkbenchTodos`），统计口径收在页面底部可展开区域；原 `WorkbenchTrend` / `WorkbenchTrendRange` 已删除。指标、待办筛选和报表均由后端返回；详情跳转、加载、失败、导出反馈在前端管理。完整口径与接口见[发票工作台](../../../../docs/invoice-workbench.md)。

## 业务状态分区与筛选（2026-10-23）

- 工作台不提供供应商、报关单创建日期筛选栏。漏斗卡点中“待财务审核”进入财务核对（待审核），其余进入开票跟进对应节点（`taskListPath({ node })`）；地址由 `app/paths.ts` 生成。待办区域保留关键词、分类、排序与导出。
- 比对队列新增 `QueueFilters`（供应商、开票日期），三档计数随条件变化。

## 只看异常与申报价校验（2026-10-23）

## 发票文件批量上传（2026-10-26）

比对队列页标题右侧“批量上传发票文件”打开 `components/InvoiceFileUploadDialog.tsx`，由统一组件库 `BatchUpload` 组合；接口在 `api/invoice-file-api.ts`，类型与结果中文映射在 `types/invoice-file.ts`。识别不了号码或匹配多张发票的文件可填写发票号码后单独重传；能否归档、保存位置全部以后端结果为准。

## 总体工作台对齐设计稿（2026-10-27）

- 关键指标用 `MetricCard`（首张 `featured="solid"` 实底，右上角 `badge` 标明财务 / 采购），数值、对比说明、提示与近 6 个月走势全部来自后端 `kpis`。
- 漏斗六步、整体完结率与卡点分项来自后端 `funnel`；六步计数用 `HorizontalBarChart` 左对齐展示，零值不画色条；顶部不显示更新时间与手动刷新按钮。趋势用 `TrendChart grouped lineAxis="percent"`；节点分布用 `DonutChart`；供应商排行与不一致分类条长为后端百分比（`Progress`）；置信度堆叠条只按后端计数画宽度。
- 比对队列页读取 `?tier=high` 作为初始分档（`matchingQueuePath`），供工作台“高置信度可批量通过”进入。
- 按用户决定不做视角切换、统计区间与页头导出报表。口径见[总体工作台](../../../../docs/invoice-workbench.md)。

## 整票审核队列与双栏详情（2026-10-28）

- `/matching` 改为每张发票一行，使用 `POST /api/matching/invoice-queue/query`；票面价税合计与待审核建议条数分开展示。计数、筛选和分页由后端按发票处理，置信度按该票全部待审核建议的最低值分档。只有全部建议均可直接通过的发票可以勾选；批量结果仍按建议条数反馈，超过 100 条分批提交，失败停止后续提交并刷新核实。
- `/matching/:invoiceId` 沿用单票路由：左侧切换明细，右侧为置信度环、发票与子采购开票口径、默认展开的逐项比对和审核表单，下方自动读取候选。已关联与历史记录保留；换算证据、说明、版本校验和容量控制仍由后端负责。提交期间禁止切换明细。
- 候选查询与选用不会直接写入分配。已有建议须先驳回；已确认记录可使用原有原子替换。候选失败、空结果、无明细与审核错误均展示真实状态。
- `ChecksTable`、`CandidateTable`、`QueueTable` 使用统一 `DataTable`，详情面板使用 `Card`，置信度使用新增共享 `ProgressRing`。旧队列逐建议表格与详情自造卡片样式已移除；保留已关联表格所需样式。
- 针对性测试：`backend/tests/test_matching_invoice_queue.py`、`backend/tests/test_matching.py` 的 HTTP 用例，以及 `frontend/tests/workbench.test.mjs` 的整票队列、明细导航和候选限制用例。

## 发票比对查询栏（2026-10-28）

`QueueFilters` 新增发票号码输入，将供应商下拉替换为供应商名称搜索。两个输入复用 `SearchInput`，仅显示框内提示并保留读屏标签，支持部分内容、逗号/分号分隔及多行粘贴。保留建议类型及开票日期起止；回车或查询提交，清除恢复全部条件，查询回到第一页并清空选中发票。前端不拆分或过滤业务数据，由后端统一查询、计数、分页。
