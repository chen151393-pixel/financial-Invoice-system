# 自动匹配页面

路由 `/matching?invoiceId=数据库主键`，由进项发票“查看”进入。MatchingPage显示真实票面、备注定位结果和子采购逐行候选，金额、差额、剩余额度及可确认状态均来自后端；缺失、无候选、错误、加载状态单独展示。多个可分配候选明确提示，由人工选择。

AllocationForm收集本次分配数量，确认调用真实接口保存本地关联；支持分批及多单逐次分配，不写NS。提交中禁用操作，失败保留输入和请求标识，重试沿用原键；修改数量前刷新核实已保存记录。成功重新获取候选及历史分配，来源变化提示待复核。api复用公共HTTP与发票类型，样式限定matching-workspace。窄屏左右面板改为上下排列。

确认依赖业务库迁移0004；购方、币种未核实或红冲等情况显示后端禁用原因，不模拟成功。接口及规则见[后端说明](../../../../backend/modules/matching/README.md)。前后端同时更新后重启后端；旧接口会明确提示需要重启，避免页面空白。

验证：前端build、lint、typecheck；规则测试见后端matching模块。

整票关联由后端 `/links/review` 复核当前选择，供应商名称、品名、单位及数量金额差异直接显示报警。存在差异时，用户勾选已核实并填写说明，再通过 `/links` 保存本地关系；已保存历史显示“存在差异，已人工确认”、确认说明及原差异。人工确认不改写票面、不生成分配额度、不写NS；购方、币种、明细完整性、红冲／作废和已占用等硬性限制仍由后端控制。

`ManualPurchaseSearch` 先按单号／供应商／品名搜索，按采购明细展示结果；每条采购明细可选择对应发票行，支持一张子采购单的多条明细分别对应多行发票，批量加入候选区。搜索不再受顶部单行发票下拉框限制，复用不传 `invoiceLineId` 的现有后端查询。查询和分页均由后端处理，跨页保留当前勾选。加入后自动收起搜索区，勾选和取消统一在候选区完成，删除重复的“已选关联”列表。

候选差异显示为一行摘要，展开后查看完整比较值与原有数量分配；提交前的差异列表同样折叠展示。金额和数量仅用字符串去除无意义的尾零，不作舍入或金额计算。匹配页只读搜索和复核遇到401会恢复本机会话并重试一次，保存接口不自动重试。

明确的400/422表单错误可修正后重新提交；网络或提交结果不明时锁定本次请求，先刷新核实，重试沿用原请求标识。已有整票关联时禁用新增选择。匹配模块复用公共请求的 `HttpError.status` 区分确定的参数拒绝与结果不明。

2026-09-24 在隔离测试数据中验证桌面和390px窄屏、报警可见、手动搜索、空结果、移除选择、后端必填校验、失败后输入保留、人工确认保存与历史回显；检查了键盘焦点和页面溢出。未在真实发票上提交关联。

本次简化验证增加同一子采购单关联两行发票的后端回归测试；真实页面仅做手动搜索、批量加入和只读复核，未提交真实关联。
