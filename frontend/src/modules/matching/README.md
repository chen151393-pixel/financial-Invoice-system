# 发票比对页面

架构 v2 第 4d 步重建。后端规则见[后端 matching 模块](../../../../backend/modules/matching/README.md)。

| 路径                   | 页面                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `/matching`            | `pages/MatchingQueuePage.tsx`：待审核建议队列，按置信度筛选，批量通过高置信度且无需说明的建议 |
| `/matching/:invoiceId` | `pages/MatchingInvoicePage.tsx`：左侧发票行导航、右侧选中行详情；手动关联、删除关联、通过 / 驳回，重新生成建议 |

旧地址 `/matching?invoiceId=…` 跳转到 `/matching/…`。外壳在 `app/MatchingWorkspacePage.tsx`，侧栏菜单名为"发票比对"。

## 文件

| 目录                | 内容                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `api/index.ts`      | 全部接口（其他模块只能经此导入，如发票列表读取比对摘要）                                                                                      |
| `types/matching.ts` | 与后端 VO 一致的类型；置信度分档与比对结果的中文映射只在这里维护                                                                              |
| `components/`       | `AllocationCard`（一条建议或分配及其操作表单）、`ChecksTable`（逐项比对）、`ManualAllocation` + `CandidateTable`（候选查询与手动关联）、`QueueTable`（审核队列）、`InvoiceLineNav` / `InvoiceLinePanel`（发票行导航与选中行详情）、`LinkedAllocations`（已关联列表与删除关联）、`allocation-groups.ts`（按后端状态分组展示） |

## 规则

- 能否通过、为什么不能通过、需要填写说明的原因都来自后端 `confirm` 与 `noteReasons`；提交时后端重新校验，失败显示真实原因并保留输入，不自动重试。
- 只读查询遇到会话失效时恢复一次；写操作不自动重试。人工分配沿用同一请求标识，结果不明时重试不会重复分配。
- 通过、取消后显示后端返回的最新比对视图；任务收票进度在"开票跟进"中查看。
- 选中行的分配按后端状态分三组展示：已关联（已通过且依据有效）、待处理（待审核建议或需重新核实）、已驳回或已取消。“删除关联”调用后端取消分配接口：原因必填、记录保留可追溯、收票进度由后端回退；能否删除只看 `cancel.allowed`。
- 审核队列后端只支持按置信度分档筛选，暂无关键词与审核条件筛选，页面不在前端过滤当前页冒充搜索。

## 验证

`npm.cmd run build`、`npm.cmd run lint`、`npm.cmd run typecheck`、`npm.cmd run check:architecture`。2026-10-15 在本地隔离 SQLite（合成数据，经真实接口预置）上做浏览器检查：队列分档计数、批量通过两条高置信度建议后任务自动"已完成"、低置信度建议未填说明被后端拒绝、填写说明后通过并显示超开、取消分配后任务退回收票前节点且流转记录可见、旧地址跳转、375px 窄屏无页面横向滚动。人工分配仅由后端测试覆盖，未在浏览器中提交。

## 发票工作台

新增正式入口 /workbench（默认首页），复用本模块只读汇总接口。页面依次为环节卡片（`WorkbenchMetrics`：待财务核对 → 待开票任务 → 待比对 / 复核 → 本月任务完成）、待办表格与供应商待收票排名（`WorkbenchTodos`、`WorkbenchSuppliers`）、已开票金额趋势（`WorkbenchTrend`），统计口径收在页面底部可展开区域。指标、待办筛选和报表均由后端返回；详情跳转、加载、失败、导出反馈在前端管理。完整口径与接口见[发票工作台](../../../../docs/invoice-workbench.md)。
