# NS 回写页面

`/writeback` 为真实任务列表，`/writeback/:requestId` 显示回写任务详情。沿用既有路由参数名，值为后端任务 ID。

查询栏分为任务号、发票号码、供应商、母采购单号四个独立搜索框，复用 `WritebackSearch` 与统一查询栏；组合条件发送后端并随 URL 恢复，卡片切换保留已提交条件、回到第一页。列表“母采购单”列展示后端任务审核快照中的全部去重母单，不把前端候选当作已关联母单；快照缺失显示“未记录”，缺单号但有内部 ID 时明确显示 NS ID。旧版含 `keyword` 的网址继续使用旧查询语义，并明确显示可清除的综合关键词提示。

列表沿用财务核对页的 `StatGrid/StatCard` 四卡概况（待回写、回写中、NS 已登记、需处理），列表标题右侧复用 `Segmented`，另保留全部任务和审核已失效入口。细分下拉保留后端返回的全部 12 种状态；成功、执行中、阻塞等使用有文字的语义徽标。统计按当前已提交的组合条件由后端汇总，卡片与切换栏不受当前状态或页码影响；点击保留组合搜索条件、清除细分状态并回到第一页。查询、细分状态、分组和分页写入 URL，刷新及前进后退可恢复；加载时保留最近计数，空结果可清空筛选，失败可重试。状态分组只是列表导航，不改变写入和人工核实规则。

- 列表由后端搜索、筛选和分页；状态、原因和允许动作由后端返回。
- 详情按子采购单汇总审核分配并可展开核对明细，展示候选账单、目标方案和审计记录。金额保持十进制字符串。
- 查询阶段查到同供应商、同完整号码的有效发票登记时，详情展示“NS 已有同号发票登记”及已有记录 ID、号码、日期，隐藏确认方案和执行回写入口；新旧任务统一归入“NS 已登记”统计及分组，细分徽标显示成功色的“NS 已有同号登记”，保留原状态与登记来源。历史任务缺少核对结果时显示后端要求重新查询的原因。
- 人工确认按整张子采购单选择账单，金额只读，每张子采购单不可拆分；不同子采购单可选择同一或不同账单，写入金额按账单汇总。保留归属依据和实际 NS 子公司核实。请求携带当前 revision 与稳定 requestId；失败不伪装成功、不自动重试确认。
- 匹配发票详情通过公开 API 显示整票就绪原因和当前任务链接；可重新检查历史发票。
- 已删除原手工预览/执行演示 API、demo1/demo2 数据与不再引用的旧组件和样式。历史演示 URL 不再有模拟成功行为。
- 方案冻结后显示“NS 回写预览”（`components/WritePanel.tsx`）：逐账单写前、本次、写后累计与明细差额，金额全部为后端字符串。累计与明细不一致时须勾选核对后“确认回写预览”。
- 仅当后端 `actions.execute` 为真时显示“回写到 NS”，确认弹窗说明写入对象、范围和不可自动撤回；不允许时显示后端原因（开关、白名单、接口未配置）。
- 点击“确认回写”立即以“正在回写…”禁用执行按钮，顶部显示正在回写提示；同步提交锁阻止快速重复点击。刷新后若后端仍为 `executing`，保持禁用并每 2 秒只读查询状态，结束后展示真实结果。写入请求异常只读核实，不自动重发；状态仍无法核实时禁用业务操作，须先刷新任务状态。旧查询响应不会覆盖操作后的新状态。
- 结果不明或部分写入时显示“核实 NS 写入结果”（`components/ResolveForm.tsx`），只提交核实结论与依据；没有重试或直接重发按钮。“NS 没有任何写入”选项仅在后端允许时出现。

接口与部署见 [后端模块](../../../../backend/modules/writeback/README.md)、[部署说明](../../../../docs/ns-writeback-prepare.md)。验证：前端 lint、typecheck、build，`tests/writeback.test.mjs` 覆盖实际接口参数（含预览确认、写入、核实）、错误与关键状态展示。
