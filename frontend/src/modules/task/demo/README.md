# 开票跟进优化示例

入口：`/tasks/workflow-demo`，沿用登录、正式开票跟进的外壳与节点分区。仅提供隔离原型，不加入正式导航。

## 内容与文件

- `WorkflowDemoPage.tsx`：节点、处理事项与关键词筛选，以及加载、空结果、失败预览。
- `DemoFollowupRow.tsx`：沿用现有任务行，常驻卡点、金额进度、承诺日期和最近联系；流程按需展开，核票与催票在当前行处理。
- `DemoInvoiceReview.tsx`：本任务候选发票、逐项差异、连续处理与演练结果。
- `DemoFollowup.tsx`：锁定当前任务的承诺日期填写、通知草稿预览。
- `workflow-data.ts`、`followup-presets.ts`：虚构任务、发票与预置状态，样例业务日为 2026-10-26。

上一版三个独立页签与侧栏待办队列已移除；核票和催票组件复用为任务行内内容。旧地址的 view 参数不再切换独立视图。

## 边界

无业务 API 请求，不访问 NS、企微或业务数据库。金额、进度、差异、节点与操作资格均为固定样例，不作为业务算法。候选发票没有计入有效收票，因此可能与“待供应商开票”节点同时出现。顶部节点数字为完整样例分布，列表支持额外筛选。

样例筛选只服务于用户明确要求的原型。日期修改只影响草稿，不重算超期；关闭处理区、筛选移出任务、重置或刷新会清空对应临时输入；演练不会修改收票进度或表示通知成功。

正式接入须由后端提供关联查询、承诺日期持久化、筛选统计、操作权限和实时校验，跨模块读取遵循 public 门面，变更通过事件。不得把演示数据适配器接入正式页面。正式功能验收后可整体删除本目录、独立装配页及路径/路由登记。

## 验证

执行前端构建、lint、类型检查和 test:web。交互检查覆盖节点/事项/关键词筛选、任务内核票与差异阻止通过、连续下一张、催票草稿日期联动、流程展开、收起后焦点、重置及页面状态。实际结果以交付说明为准。
