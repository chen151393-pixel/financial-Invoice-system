# 开票跟进页面

## 组合搜索（2026-10-28）

“维护供应商档案”复用统一 `Dialog`，按供应商身份 → 外部群查找／已选群与绑定状态 → 保存操作排列；桌面双栏，小屏按阅读顺序排列。搜索输入预填当前供应商名称，保持默认名称（或清空）时仍调用后端自动匹配，修改为简称／群主等关键词时手动查找。初始不自动访问企微，不自动选择或保存群；保存期间禁止关闭，完成后返回原维护入口或结果提示。

供应商档案顶部概况卡可点击筛选全部、已绑定开票群、未绑定开票群、已关闭通知。复用 `StatCard` 的按钮与选中态；切换保留已应用的名称／群名／群主条件并回到第一页，状态写入 URL，刷新或前进后退可恢复。已绑定包含群绑定启用和停用两类；已关闭通知按供应商通知开关筛选，独立于群绑定状态。查询栏下拉与卡片状态同步，空结果仍可切换卡片。

原混合关键词和供应商下拉已替换为三个独立输入框：供应商、CD 号、子采购单号。`BoardSearch` 复用 `FilterBar`、`Field` 和 `Button`；可单独或组合查询，多个条件同时满足，匹配与校验均由后端处理。正式接口为 `/api/task/board/query`。

点击查询或回车提交并回到第一页；切换节点、翻页和刷新保留已提交条件。清除搜索保留当前节点，“查看全部进行中”同时清除节点。查询与分页经 `hooks/board-query.ts` 保存在 URL，刷新后恢复。旧链接的供应商 ID、关键词、阶段与日期范围会显式展示并允许清除；填写供应商名称后查询会替换原供应商 ID 范围。加载、空结果、失败沿用统一状态组件。

架构 v2 第 4c 步由 `reconciliation` 移出，改用 task 模块新接口。后端规则见[后端 task 模块](../../../../backend/modules/task/README.md)。

| 路径         | 页面                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| `/tasks`     | `pages/TaskBoardPage.tsx`：统一开票跟进，任务节点、关键词与供应商查询、合并任务面板、逐任务分页、批量上传回签合同 |
| `/tasks/:id` | `pages/TaskDetailPage.tsx`：六节点流程、合同、通知、流转记录                                                      |
| `/suppliers` | `pages/SupplierGroupsPage.tsx`：供应商档案：已同步供应商及默认企微群                                              |

旧地址 `/invoice-followup`、`/invoice-followup/supplier-groups` 跳转到新地址；旧任务详情地址跳转到任务列表（旧任务不迁移）。外壳在 `app/TaskWorkspacePage.tsx`。

开票跟进按“节点卡片（进行中合计 + 六个节点一行排开）→ 列表卡片（标题、批量上传回签合同、内嵌查询栏、任务卡片、分页）”排列；节点切换、查询、清除和刷新仍使用现有后端查询，节点说明由后端 `NODE_HINTS` 给出。

每张任务卡片展示节点字标、供应商、当前状态、单据、待收金额、收票进度、等待天数；右侧按钮只有“收起/展开流程”和最右侧的“跟进详情”，不放节点操作按钮，也不显示下一步说明（2026-10-27 按设计稿调整）。六节点流程默认展开；阻塞原因始终展示，不随流程折叠隐藏。

任务详情：进入页面即停在后端标记的当前节点（地址带 `#task-节点` 时以地址为准）。上方为概览（状态、等待天数、应开 / 待收与收票进度、可点击的六个节点）；左侧“当前节点”卡片放该节点的处理内容（合同与报关资料、通知供应商、等待收票、发票比对入口、补齐完结资料），查看其他节点时可“回到当前节点”；其下为应开明细与收票进度（含差异结束）；右侧为完结资料、流转记录与任务信息。

## 规则

- 按钮可用与原因只来自后端 `allowed/reason`；状态文案、应开金额合计由后端返回。
- 列表统计显示进行中总数及六个当前节点的任务数；收票进度（应开明细中的已收数量与金额）由发票比对通过的分配汇总，详情页“等待收票”展示、“比对结果”链接到比对审核队列。
- 合同保存、通知登记失败时显示后端真实错误，不自动重试。

## 供应商档案维护

侧栏“基础资料 → 供应商档案”进入 `/suppliers`；旧 `/tasks/supplier-groups` 和 `/invoice-followup/supplier-groups` 重定向到此页，兼容一版本后清理。此页继续归属 task，开票跟进引用同一份绑定。

`SupplierGroupsPage` 使用 `useSupplierProfiles` 查询真实供应商（包括未绑定），`SupplierProfilesTable` 展示群、群主、NS 身份和绑定状态；筛选/分页保存在 URL。每行“维护档案”打开现有编辑区，初始不请求企微；点击“查找外部群”（或在输入框按回车）后查询本地目录，输入关键词则按关键词查找，留空则由后端按供应商名称自动匹配。首次查询后显示“同步群目录”，只提交后台同步请求并立即返回已有目录。手动选择群后保存并实时核验。没有虚构联系人或采购负责人。

匹配依据与排序来自后端，前端只展示；改变关键词可查简称、群主和群 ID。已保存的绑定不会因推荐变化自动覆盖。保存失败保留选择，旧响应不覆盖新查询；取消返回触发按钮。原 GroupLookup 供应商二次选择组件退出，此页直接从档案行进入维护，不再重复查询选择供应商。

群查询结果通过 `WecomDirectoryStatus` 展示后端返回的目录更新时间、过期、排队、分页发现数量、详情已处理/总数、百分比及失败信息。首次没有完整目录时不显示“没有匹配群”；后台刷新期间已有候选仍可查询和选择。`pollWecomDirectory` 仅在响应 `directoryRefreshing=true` 时每 1.5 秒串行读取当前查询，后续请求固定 `refresh=false`；完成、失败、关闭或切换查询时停止，取消请求并忽略旧响应。读取进度失败保留已展示结果，提示用户点击查找重试；不会自动重放同步或保存。百分比与过期判断来自后端；新增字段缺失时兼容旧响应。

验证入口增加 `frontend/tests/supplier-profiles.test.mjs`，覆盖独立导航、未绑定供应商、群主身份展示及失败不自动重放。真实企微权限与目录完整性需部署环境联调。

## 外部群导入与关联

从供应商档案右上角“外部群导入与关联”进入 `/suppliers/external-groups`。

1. 上传七列 `.xlsx`（保留群人数、创建时间两列，内容可空或任意格式，无法识别时显示“未提供”），可指定用于推荐的 NS 环境。后端生成持久预览，URL 的 importId 可恢复预览。
2. 唯一且无冲突的候选预选；错误行不可关联。逐行“匹配供应商”可以按名称搜索来源供应商，选中后查看确认清单。多群争用一个供应商时不预选。
3. “确认导入并保存所选绑定”保存所有有效群及选中关联，跳过已展示的错误行。没有关联的群保留在目录。
4. 目录支持按群/群主/ID 搜索及已关联/未关联筛选；“关联供应商”允许日后调整。替换原默认群需明确勾选确认。

预览有效期 24 小时，刷新会丢弃未提交的人工选择并恢复初始推荐；确认失败保留当前选择，不自动重试写入。已确认预览不能换一组选择重新提交。Excel 信息标明来源，未使用企微实时核验。新页面只收集选择并展示后端候选和规则，不在前端匹配供应商或筛选业务行。

`GroupImportUpload`、`GroupImportPreview`、`ExternalGroupCatalog` 分别负责上传、预览确认与后续维护，共用 `SupplierAssociation`。原文件读取与发票导入共用 `shared/api/import-file.ts`。组件拆分行展示以遵守文件上限。测试见 `frontend/tests/external-groups.test.mjs`。

## 企微通知提交与回执（2026-10-19）

任务详情通知区接入 `WecomNotification` 和 `useDelivery`，请求集中在 `api/delivery.ts`。沿用原生 dialog 和 Button，不增加新路由。先保存通知，再查看后端冻结预览，确认后提交正文和合同；界面只展示版本、目标群、群主、合同清单与实际状态。

已提交显示“待群主确认”，页面可见且后端允许轮询时每 30 秒刷新；隐藏、离开通知区或进入终态即停止。失败不自动重放提交；浏览器重开只读取台账。unknown 仅提供证据查询和唯一候选关联，不提供任意消息编号或无证据重置。人工输入群名/员工只用于人工通道，企微目标取供应商绑定及实时群主。

`test:web` 已包含 `wecom-notification.test.mjs`，检查请求不带任意目标/路径、失败不重试、未知状态和禁用操作。部署见[企微通知方案](../../../../docs/wecom-supplier-notification-plan.md)。本次浏览器验证仅使用合成数据及假企微。

## 统一开票跟进（2026-10-26）

原采购任务台替代旧平铺列表，唯一正式入口为 `/tasks`。旧 `/tasks/board` 保留一个版本的重定向，携带查询和锚点；内部跳转已统一到 `/tasks`，旧书签完成迁移后可删除兼容地址。原列表页及专用表格、分组工具栏、统计样式已移除。任务详情、供应商档案、回签合同后台上传继续复用。

来自发票工作台的 `stage`、`supplierId` 和旧链接中的 `createdFrom/createdTo` 由节点查询接口继续处理；页面显示已应用范围，并可清除。业务阶段仍按报关单下最慢阶段判定，未选择节点时包含该范围内已完成的同单任务，不在前端换算成节点条件。

金额、进度、等待文案来自后端，缺失值不当作零。`tests/task-followup.test.mjs` 覆盖默认展开、阻塞原因、详情入口、金额精度及范围参数。

## 去掉 NS 环境筛选（2026-10-26）

上线只同步 NS 正式环境，开票跟进列表与供应商档案查询栏不再提供 NS 环境 / 账套筛选，地址里的 `account` 参数也不再读取（旧链接带 `?account=` 时按不限处理）。后端查询参数保留为可选，不传即不限；列表行内的 NS 环境文字仍照常显示。

## 回签合同上传队列

`SignedContractUpload` 复用统一组件库的进度、表格与状态组件；`useSignedUploads` 经 `api/signed-upload.ts` 创建批次、逐片传输和轮询。单文件最高 100 MB，批量选择后每 20 个一批；大小和格式由后端判断，前端按后端分片大小切片，不整批读取 Base64。每个文件传输失败保留在对应行，可继续上传；后台匹配/归档失败可补单号后重新排队。完整接收后可关闭弹窗或页面，再次打开查询当前用户最近 20 批，处理进度不依赖浏览器。传输未完成时须保持页面打开；页面关闭后未传完的文件需重新选择。原上传 API 及类型已从前端移除。

## 供应商档案批量搜索（2026-10-28）

`SupplierProfileSearch` 替换混合搜索框，分为供应商名称、外部群名称、群主姓名或账号，三个输入框仅显示框内提示。复用 `SearchInput` 支持逗号/分号分隔及粘贴多行；条件和页码保存在 URL，提交和清空回到第一页。保留绑定状态、刷新与外部群导入入口。列表请求切换为 `/api/task/supplier-groups/profiles/query`；输入解析、AND/OR 匹配、数量及分页均由后端处理。
