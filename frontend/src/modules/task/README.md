# 开票跟进页面

## 流转记录步骤与操作人（2026-11-27）

`TaskHistory` 直接展示后端 `history`，不再合并原事件与合同或用 JavaScript 毫秒时间重新排序。最新操作仍在前面，但有序列表使用每条记录的 `sequence` 显示真实步骤号，最早生成任务为第 1 步；同一时间按后端确定的先后顺序展示。操作人展示 `actorName`，原始 `actor` 保留在提示中供核查。空记录复用 `EmptyState`，保留任务编号。测试见 `task-followup.test.mjs`。

## 销售合同下载区暂时隐藏（2026-11-26）

`DeclarationDocuments` 在资料准备节点按报关单展示报关单文件、销售合同、发票文件三列。销售合同只展示状态，继续隐藏错误详情、路径及下载/重试入口；报关单和发票保留文件信息与真实下载操作。接口、后端归档记录和完结资料判定保留，缺件提示仍展示后端返回的真实结果。

## 审核与资料表格（2026-11-26）

详情页保持六节点切换。`TaskReview` 按后端 `reviewRows` 展示任务生成时的海关/财务审核依据、CD/真实报关单号、审核版本和子采购单张数；依据失效时同时展示后端原因，不把历史通过表述为当前仍有效。资料准备中的子采购合同只显示子采购单号、保存路径、报关单及归档状态，保留保存/重试及前往通知供应商入口。其下保留报关单、发票的下载/重试，复用 `DeclarationDocuments` 与后端 `declarationRows`，每份资料操作保留原 `taskId`。回签合同同样位于资料准备中，默认折叠，展开后查看和上传，上传完成后刷新真实状态。统计由 `preparation` 返回，不在前端重算；“完成”节点保留完结条件与缺件说明，通过“查看合同与资料”返回资料准备。通知页的合同展示沿用完整文件信息。

## 组合搜索（2026-10-28）

“维护供应商档案”复用统一 `Dialog`，按供应商身份 → 外部群查找／已选群与绑定状态 → 保存操作排列；桌面双栏，小屏按阅读顺序排列。搜索输入预填当前供应商名称，保持默认名称（或清空）时仍调用后端自动匹配，修改为简称／群主等关键词时手动查找。初始不自动访问企微，不自动选择或保存群；保存期间禁止关闭，完成后返回原维护入口或结果提示。

供应商档案顶部概况卡可点击筛选全部、已绑定开票群、未绑定开票群、已关闭通知。复用 `StatCard` 的按钮与选中态；切换保留已应用的名称／群名／群主条件并回到第一页，状态写入 URL，刷新或前进后退可恢复。已绑定包含群绑定启用和停用两类；已关闭通知按供应商通知开关筛选，独立于群绑定状态。查询栏下拉与卡片状态同步，空结果仍可切换卡片。

原混合关键词和供应商下拉已替换为三个独立输入框：供应商、CD 号、子采购单号。`BoardSearch` 复用 `FilterBar`、`Field` 和 `Button`；可单独或组合查询，多个条件同时满足，匹配与校验均由后端处理。正式接口为 `/api/task/board/query`。

点击查询或回车提交并回到第一页；切换节点、翻页和刷新保留已提交条件。清除搜索保留当前节点，“查看全部进行中”同时清除节点。查询与分页经 `hooks/board-query.ts` 保存在 URL，刷新后恢复。旧链接的供应商 ID、关键词、阶段与日期范围会显式展示并允许清除；填写供应商名称后查询会替换原供应商 ID 范围。加载、空结果、失败沿用统一状态组件。

架构 v2 第 4c 步由 `reconciliation` 移出，改用 task 模块新接口。后端规则见[后端 task 模块](../../../../backend/modules/task/README.md)。

开票跟进按“节点卡片（进行中合计 + 六个节点一行排开）→ 列表卡片（标题、批量上传回签合同、内嵌查询栏、任务卡片、分页）”排列；节点切换、查询、清除和刷新仍使用现有后端查询，节点说明由后端 `NODE_HINTS` 给出。

每张任务卡片展示节点字标、当前状态、待收金额、收票进度、等待天数；按供应商合并时以供应商为主标题，CD 编号为次要信息；按报关单分开时以“CD 编号 · 真实报关单号”为主标题，供应商与采购公司为次要信息，真实报关单号缺失时明确提示待补充。单号区不列出子采购单号。右侧仅保留“跟进详情”，六节点流程常驻展开，阻塞原因始终展示（2026-11-26）。沿用原任务卡片样式，不在列表生成通知或重复放资料入口。

列表默认“按供应商合并”，可切换“按报关单分开”；`groupBy` 随查询和分页保存在 URL，清除条件不改变当前视图。分组范围、统计、金额与能力均由后端返回。供应商合并卡片跳转 `/tasks/supplier/:taskId`，报关单视图跳转原 `/tasks/:taskId`；完成组通过 `?completed=1` 保留历史范围。详情继续使用原六节点切换界面，集中展示各报关单资料、全部子采购合同与应开明细，单份资料和差异结束操作仍调用原归属任务接口。

合并通知从后端带出全部待通知子采购单与附件；通知区的“本次通知对应合同”默认收起，可点击或通过键盘展开/收起；归档进度及未齐提示始终显示。明细复用 `PurchaseContracts` 的只读表格，使用后端 `notificationDocuments` 展示本次范围全部合同的原报关单、待保存/保存失败/已保存状态、失败原因与可展开的归档详情，不按已归档附件文件名过滤。归档份数与是否齐全的提示使用后端 `scopeReason`，未齐时明确要求先归档；合同补存继续在“资料准备”办理。保存、人工登记携带 `scopeRevision`，保存另生成请求 UUID，不自动重试。企微操作使用后端的 `notificationTaskId`，复用原不可变预览、未知结果核实与轮询。已通知或进入收票的成员保留资料与记录，不再加入本次通知。前端不合并账本、不计算金额，也不自行判断业务能否执行。

任务详情：进入页面即停在后端标记的当前节点（地址带 `#task-节点` 时以地址为准）。当前节点按已发生的业务事实推进，被越过但事实未发生的节点为 `skipped`（如“未通知即收票”），`Stepper` 以虚线圈“–”显示（2026-11-17）。上方为概览（状态、等待天数、应开 / 待收与收票进度、可点击的六个节点）；左侧“当前节点”卡片放该节点的处理内容（合同与报关资料、通知供应商、等待收票、发票比对入口、补齐完结资料），查看其他节点时可“回到当前节点”；收票概况卡与应开明细（含差异结束）仅在选择“发票比对”节点时显示；收票概况展示后端的应开合计、已收金额、待收金额，以及各原任务的报关单、子采购单和金额、任务状态，支持查看通知与催票。未知金额显示待确认，不在前端按差额或百分比反算已收；右侧为完结资料、流转记录与任务信息。

## 规则

- 按钮可用与原因只来自后端 `allowed/reason`；状态文案、应开金额合计由后端返回。
- 列表统计显示进行中总数及六个当前节点的任务数；收票进度（应开明细中的已收数量与金额）由发票比对通过的分配汇总，详情页仅在“发票比对”节点展示明细与进度，并提供比对审核队列入口。
- 合同保存、通知登记失败时显示后端真实错误，不自动重试。

## 供应商档案维护

侧栏“基础资料 → 供应商档案”进入 `/suppliers`；旧 `/tasks/supplier-groups` 和 `/invoice-followup/supplier-groups` 重定向到此页，兼容一版本后清理。此页继续归属 task，开票跟进引用同一份绑定。

任务通知区“维护供应商档案”跳转时，通过 URL 的 `supplierName` 带入当前任务供应商名称，档案页自动填入并查询，从第一页展示，不附加绑定状态限制；刷新后保留筛选，也可通过“清空”恢复全部供应商。单任务与供应商合并任务复用同一入口。

`SupplierGroupsPage` 使用 `useSupplierProfiles` 查询真实供应商（包括未绑定），`SupplierProfilesTable` 展示群、群主、NS 身份和绑定状态；筛选/分页保存在 URL。每行“维护档案”打开现有编辑区，初始不请求企微；点击“查找外部群”（或在输入框按回车）后查询本地目录，输入关键词则按关键词查找，留空则由后端按供应商名称自动匹配。首次查询后显示“同步群目录”，只提交后台同步请求并立即返回已有目录。手动选择群后保存并实时核验。没有虚构联系人或采购负责人。

匹配依据与排序来自后端，前端只展示；改变关键词可查简称、群主和群 ID。已保存的绑定不会因推荐变化自动覆盖。保存失败保留选择，旧响应不覆盖新查询；取消返回触发按钮。原 GroupLookup 供应商二次选择组件退出，此页直接从档案行进入维护，不再重复查询选择供应商。

群查询结果通过 `WecomDirectoryStatus` 展示后端返回的目录更新时间、过期、排队、分页发现数量、详情已处理/总数、百分比及失败信息。首次没有完整目录时不显示“没有匹配群”；后台刷新期间已有候选仍可查询和选择。`pollWecomDirectory` 仅在响应 `directoryRefreshing=true` 时每 1.5 秒串行读取当前查询，后续请求固定 `refresh=false`；完成、失败、关闭或切换查询时停止，取消请求并忽略旧响应。读取进度失败保留已展示结果，提示用户点击查找重试；不会自动重放同步或保存。百分比与过期判断来自后端；新增字段缺失时兼容旧响应。

验证入口增加 `frontend/tests/supplier-profiles.test.mjs`，覆盖独立导航、未绑定供应商、群主身份展示及失败不自动重放。真实企微权限与目录完整性需部署环境联调。

## 外部群导入与关联

从供应商档案右上角“外部群导入与关联”进入 `/suppliers/external-groups`。

1. 上传七列 `.xlsx`（保留群人数、创建时间两列，内容可空或任意格式，无法识别时显示“未提供”），可指定用于推荐的 NS 环境。后端生成持久预览，URL 的 importId 可恢复预览。
2. 唯一且无冲突的候选预选；错误行不可关联。逐行“匹配供应商”可以按名称搜索来源供应商，选中后查看确认清单。多群争用一个供应商时不预选。
3. “确认导入并保存所选绑定”保存所有有效群及选中关联，跳过已展示的错误行。没有关联的群保留在目录。
4. 目录支持按群/群主/ID 搜索及已关联/未关联筛选；“关联供应商”允许日后调整。替换原默认群需明确勾选确认。

预览有效期 24 小时，刷新会丢弃未提交的人工选择并恢复初始推荐；确认失败保留当前选择，不自动重试写入。已确认预览不能换一组选择重新提交。Excel 信息标明来源，未使用企微实时核验。新页面只收集选择并展示后端候选和规则，不在前端匹配供应商或筛选业务行。

`GroupImportUpload`、`GroupImportPreview`、`ExternalGroupCatalog` 分别负责上传、预览确认与后续维护，共用 `SupplierAssociation`。原文件读取与发票导入共用 `shared/api/import-file.ts`。组件拆分行展示以遵守文件上限。测试见 `frontend/tests/external-groups.test.mjs`。

## 企微通知提交与回执（2026-10-19）

任务详情通知区接入 `WecomNotification` 和 `useDelivery`，请求集中在 `api/delivery.ts`。沿用原生 dialog 和 Button，不增加新路由。先保存通知，再查看后端冻结预览，确认后提交正文和合同；界面只展示版本、目标群、群主、合同清单与实际状态。

已提交显示“待群主确认”，页面可见且后端允许轮询时每 30 秒刷新；隐藏、离开通知区或进入终态即停止。失败不自动重放提交；浏览器重开只读取台账。unknown 仅提供证据查询和唯一候选关联，不提供任意消息编号或无证据重置。人工输入群名/员工只用于人工通道，企微目标取供应商绑定及实时群主。

`test:web` 已包含 `wecom-notification.test.mjs`，检查请求不带任意目标/路径、失败不重试、未知状态和禁用操作。部署见[企微通知方案](../../../../docs/wecom-supplier-notification-plan.md)。本次浏览器验证仅使用合成数据及假企微。

## 回签合同上传队列

`SignedContractUpload` 复用统一组件库 `FileDropzone`、进度、表格与状态组件，支持点击多选、拖入、追加文件、移除与清空选择；`useSignedUploads` 经 `api/signed-upload.ts` 创建批次、逐片传输和轮询。单文件最高 100 MB，批量选择后每 20 个一批；大小和格式由后端判断，前端按后端分片大小切片，不整批读取 Base64。每个文件传输失败保留在对应行，可继续上传；后台匹配/归档失败可补单号后重新排队。只展示本次提交的批次，按批次 ID 轮询，不自动加载历史任务；完成后直接展示逐文件结果，隐藏完成的进度条，完整保存路径折叠查看。完整接收后可关闭弹窗或页面，后台继续处理；再次打开窗口清空选择和结果，下一轮上传也替换展示。清空展示不删除后台任务或归档文件。传输未完成时须保持页面打开；页面关闭后未传完的文件需重新选择。原上传 API 及类型已从前端移除。

## 批量登记已通知（2026-11-19）

合并卡片保留全部成员，勾选资格按后端 `notifyRecord`，确认清单按 `notifyTargets`（原任务编号、供应商、CD 号、子采购单号）。实际提交只传所选组锚点、`notifyScopeRevision` 和展示方式，调用 `record-groups`，由后端展开待通知成员并按组独立事务登记；前端不展开原任务编号、不按 50 条切分请求。单组或合计超过 50 个原任务仍可登记，同组保持完整，一组失败不影响其他组。

确认窗口按组列出 CD 号和子采购单，数量同时说明组数与待通知任务数。返回后逐组显示“整组已登记 / 整组跳过 / 结果待核实”及后端原因；范围变化须刷新后重新确认，网络失败或待核实不直接重试。已通知、合同未齐、来源失效或受合并通知保护的成员由后端排除，提交时仍重新校验。

`/tasks` 列表的批量操作沿用财务核对的交互：默认隐藏勾选框，列表卡片顶部常驻蓝色小尺寸“批量登记已通知”按钮，与“批量上传回签合同”并排；本页无可登记任务或加载中时禁用。点击后进入选择模式，仅后端 `notifyRecord.allowed` 为真的任务显示勾选框；可全选本页，也可逐项取消或重新勾选，部分选中时全选框显示半选状态。“取消批量”退出并清空选择；查询、切换节点或展示方式、翻页和刷新也退出并清空。“确认登记已通知（N）”仅在有选择时可用，打开 `components/NotifyBatchDialog.tsx` 确认本次任务组、选择通知日期、填写选填说明，并展示逐组结果及原因。

- 提交组锚点、范围版本、说明与 `notifiedOn` 日期（`api/task.ts` 的 `recordNotificationGroups`）；弹窗按北京时间默认今天，可人工选择。后端校验日期并保存，能否登记不在前端判断；完整存储规则见后端模块文档。
